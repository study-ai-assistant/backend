# Патчноуты backend

Здесь собраны изменения сервера по датам. Старые записи описывают состояние
на момент обновления. Инструкция запуска — в [README](README.md).

## Что работает сейчас

| Возможность | Текущее поведение |
|---|---|
| IDEA / Maven / JAR | Java 21; Docker для такого запуска не нужен |
| Docker Compose | Проверен 04.11.2026: сборка, healthy, /health и /modes с хоста, настройки окружением |
| Проверка связи | GET /health → 200, {"status":"ok"}; ключ не нужен |
| Техническая проверка | GET /actuator/health → состояние Spring |
| Список режимов | GET /api/v1/modes → пять идентификаторов без ключа |
| Готовый текст | POST /api/v1/text/process: JSON text и mode, все пять режимов |
| TXT | POST /api/v1/materials/process: один file и mode, UTF-8 / Windows-1251, все пять режимов |
| Лимиты TXT | 10 МиБ на файл, 30 МиБ на запрос, 10000 Unicode-кодовых точек текста |
| Ошибки | 400 — входные данные, 413 — лимит, 415 — формат, 502 — LLM |
| Groq | Реальный адаптер; нужны личные настройки и ключ. Тесты используют локальные заглушки |
| PDF / DOCX / OCR | По API не поддерживаются; PDF исследован для Спринта 3 |
| Хранение и авторизация | История, аккаунты и постоянное хранение не реализованы |

## 10.11.2026 — Извлечение текста из PDF

- Подключён PDFBox 3.0.8, исправлены Java-класс и конструктор тестов.
- PDF с текстовым слоем работает во всех режимах; TXT продолжает работать.
- Содержимое сверяется с расширением. Добавлены лимит 50 страниц и таймаут 10 секунд.
- Сканы, пароль и повреждение возвращают 422, лимиты — 413; текст не обрезается.
- Добавлены PDF-тесты и примеры curl, обновлены инструкции.

## 04.11.2026 — Загрузка TXT и обновление сервера

- TXT-файл можно отправить на `/api/v1/materials/process` в поле `file`
  вместе с `mode`. Поддерживаются все пять режимов, UTF-8 и Windows-1251.
- Исправлено чтение Windows-1251 и удаление BOM в начале UTF-8-файла.
- Добавлена проверка: в запросе должен быть ровно один файл.
- Восстановлен `/api/v1/modes` для мобильного клиента.
- Ошибки LLM при обработке файла возвращают 502, как и при обработке JSON.
  Приведены к общему формату ошибки загрузки и неверных параметров.
- Исправлены дубли и остатки конфликтов в OpenAPI и README.
- Добавлены HTTP-тесты загрузки и проверки всех режимов. Проходят 63 теста,
  включая проверку OpenAPI; JSON и TXT также проверены с настоящим LLM.
- Обновлён CI: сохраняются отчёты тестов, ограничено время выполнения заданий,
  устаревшие прогоны отменяются. Docker-проверка обращается к `/health` и `/api/v1/modes`.
- Проверен запуск через Docker Compose на Linux. Добавлен кеш Maven для сборки.
  `.env` не попадает в образ, настройки передаются при запуске.
- Подготовлены выводы по PDFBox и извлечению текста из PDF. Само приложение
  пока принимает только TXT; PDF, DOCX и OCR остаются следующими задачами.
- Обновлены инструкции запуска, API и материалы wiki.

## 24.10.2026 — Обработка текста №8 объединена с feature/server-base

- Реализация `eb70785` из `feature/8-text-processing` включена в ветку слиянием
  `32d912a` (PR №17). Запрос /api/v1/text/process больше не является заглушкой 404.
- TextProcessingController принимает ровно text и mode в application/json.
  Поддерживается только SHORT_SUMMARY, text — до 10000 Unicode-кодовых точек.
- GroqLlmClient отправляет текст и отдельную системную инструкцию в
  /chat/completions, возвращает содержимое первого ответа модели.
- Добавлены ошибки 400/413 и общий безопасный ответ 502 при проблемах Groq,
  квоте, неполных настройках и таймауте. Ожидание LLM — до 60 секунд.
- Добавлены тесты HTTP-обработки и клиента Groq с локальной имитацией API.
  После обновления документации выполнен verify: 30 тестов, 0 ошибок и пропусков,
  Checkstyle и сборка JAR прошли. Реальный Groq в этой проверке не вызывался.
- При обновлении документации синхронизированы README, API/OpenAPI, настройки,
  архитектура, тестирование, запуск, локальные страницы wiki и таблица стека.
- В .env.example удалены повторные определения переменных; реальный .env не менялся.
- Добавлен готовый JSON-пример и инструкция сериализации абзацев. Буквальный Enter
  внутри JSON-строки вызывает 400; используйте \n или JSON-сериализатор.
- **Файлы по-прежнему не обрабатываются**: /api/v1/materials/process → 501.
  TXT/DOCX/PDF, OCR и четыре других режима остаются следующими задачами.
- Spring AI не используется: текущая интеграция написана на Spring RestClient.
- Для мобильной команды доступны GET /health, GET /actuator/health,
  GET /api/v1/modes и POST /api/v1/text/process. Поля и ошибки — в docs/api/README.md.
- Изменения документации сохраняются локально; push и публикация wiki не выполняются.

## 24.10.2026 — Подготовка задач спринта и документации

### Настройки LLM — задача №6

- Добавлен `LLM_PROVIDER` вместе с уже предусмотренными `LLM_MODEL`,
  `LLM_API_KEY` и `LLM_BASE_URL`.
- Добавлен класс `LlmProperties`, к которому Spring привязывает настройки.
  Его строковое представление не раскрывает ключ.
- Учтены новые правила команды: каждый backend-разработчик выбирает провайдера
  и получает собственный ключ. Общий ключ для всех не требуется.
- В `.env.example` оставлены только названия, комментарии и пустые значения.
- Добавлены тесты чтения настроек, работы без ключа и защиты строкового представления.
- Реальный LLM-запрос не добавлялся: он относится к №8.

### JSON-контракт — задача №4

- Подготовлен черновик `POST /api/v1/text/process`:
  запрос `{"text":"…","mode":"SHORT_SUMMARY"}`, ответ `{"mode":"SHORT_SUMMARY","result":"…"}`.
- Описаны все пять идентификаторов режимов. Для первой реализации предложен
  только краткий конспект; остальные режимы — последующая работа.
- Добавлены примеры ошибок: 400 — неверный запрос, 413 — большой текст,
  502 — ошибка/таймаут/квота провайдера.
- Предложены лимит 10000 Unicode-символов и таймауты. Это условия черновика,
  которые ещё нужно согласовать с mobile и реализовать.
- Файлы не входят в контракт спринта 1. Прежний multipart-маршрут оставлен
  в коде как заглушка для совместимости.
- Добавлена автоматическая проверка структуры OpenAPI и ссылок через Swagger Parser.
  Отдельно проверено соответствие примеров схемам.

### Линтер и CI — задача №9, пока Backlog

- Добавлен Checkstyle: проверки импортов, фигурных скобок, длины строк,
  табов и некоторых ошибок оформления; проверяются основной код и тесты.
- `./mvnw verify` теперь включает линтер, тесты и сборку JAR.
- В GitHub Actions подготовлены задания `lint`, `tests` и `docker`.
- Проверки настроены для PR и push в `main`, `feature/**`, `chore/**`, `docs/**`.
  Старое имя ветки `base` больше не используется в триггере.
- GitHub Actions для новых изменений не запускался: они пока не публиковались.

### Дополнительный запуск через Docker — задача №10, пока Backlog

- Добавлены `Dockerfile`, `docker-compose.yml` и `.dockerignore`.
- Образ собирается в два этапа: сборка с JDK, запуск с JRE; сервер запускается
  от отдельного пользователя без root.
- `.env` не копируется в образ, параметры передаются окружением при запуске.
- Добавлена проверка `/health`, которую использует контейнерный healthcheck.
- `APP_PORT` задаёт порт компьютера; внутри контейнера сервер использует 8080.
- Добавлены `.gitattributes` для корректных окончаний строк Maven Wrapper на разных ОС.
- Compose проверен по официальной схеме, код healthcheck скомпилирован и проверен
  против JAR на хосте. **Сборка и запуск Docker-образа не проверены: Docker отсутствует.**
- Обычный запуск через IDEA и Maven сохранён.
