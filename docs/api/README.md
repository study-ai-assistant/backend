# API для мобильного приложения

HTTP REST, ответы JSON в UTF-8. Авторизации клиента и хранения истории пока нет.
LLM-ключ хранится на сервере в окружении / локальном `.env`, в запросы mobile не входит.
Формальная схема: [openapi.yaml](openapi.yaml).

## Эндпоинты

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/health` | Нет | 200, `{"status":"ok"}` без ключа |
| GET | `/actuator/health` | Нет | Техническое состояние Spring |
| GET | `/api/v1/modes` | Нет | JSON-массив пяти идентификаторов без ключа |
| POST | `/api/v1/text/process` | JSON: `text`, `mode` | 200, `mode` и `result` |
| POST | `/api/v1/materials/process` | multipart: `file`, `mode` | 200, `mode` и `result` |

Режимы: `SHORT_SUMMARY`, `DETAILED_SUMMARY`, `SIMPLE_EXPLANATION`,
`SELF_CHECK_QUESTIONS`, `KEY_TERMS`. Регистр важен. Все пять работают для текста, TXT и PDF.

## Запросы curl

Сервер должен быть запущен, например `./mvnw spring-boot:run` из корня backend.
Для генерации заполните LLM_PROVIDER, LLM_API_KEY, LLM_BASE_URL, LLM_MODEL в `.env`;
подробности в [README](../../README.md). В PowerShell используйте `curl.exe`.

```bash
curl -i http://localhost:8080/health
curl -i http://localhost:8080/api/v1/modes
curl -i --max-time 90 http://localhost:8080/api/v1/text/process \
  -H 'Content-Type: application/json' \
  --data-raw '{"text":"Митохондрии обеспечивают клетку энергией.","mode":"SHORT_SUMMARY"}'
```

JSON содержит ровно два поля: `text` и `mode`. Переносы внутри строки кодируются
как `\n`, буквальный перенос между кавычками делает JSON невалидным.
Для большого текста создайте корректный JSON сериализатором или используйте пример:

```bash
curl -i --max-time 90 http://localhost:8080/api/v1/text/process \
  -H 'Content-Type: application/json' \
  --data-binary @docs/api/examples/short-summary-request.json
```

Загрузка TXT (подставьте путь к своему файлу):

```bash
curl -i --max-time 90 http://localhost:8080/api/v1/materials/process \
  -F 'file=@/home/user/Documents/lecture.txt;type=text/plain' \
  -F 'mode=KEY_TERMS'
```

Один файл в поле **file**, не `files`. Не устанавливайте общий Content-Type вручную:
клиент должен сформировать `multipart/form-data; boundary=...`.
Для Android передайте одну бинарную multipart-часть `file` с именем `lecture.txt`
и текстовую часть `mode`. JSON с base64 вместо multipart не поддерживается.

Ответ для обоих POST имеет одинаковую форму (содержимое зависит от LLM):

```json
{"mode":"KEY_TERMS","result":"Митохондрии — структуры, обеспечивающие клетку энергией."}
```

## Ограничения

- Текст: 1–10000 Unicode-кодовых точек, нужен хотя бы один непробельный символ.
- TXT: расширение `.txt` без учёта регистра; рекомендуемый MIME `text/plain`.
- UTF-8 декодируется строго; если байты невалидны для UTF-8, используется Windows-1251.
  Начальный UTF-8 BOM удаляется. Автоопределение произвольных кодировок не гарантируется.
- До 10 МиБ (10485760 байт) на файл и 30 МиБ на весь multipart-запрос.
  Даже небольшой файл отклоняется, если извлечённый текст длиннее 10000 символов.
- DOCX, OCR, пакетная загрузка и обработка текста частями не реализованы.
- Ожидание LLM ограничено 60 секундами; клиенту рекомендуется таймаут 90 секунд.
  Повтор POST может вызвать повторный запрос и расход квоты.

## PDF

```bash
curl -i --max-time 90 http://localhost:8080/api/v1/materials/process \
  -F 'file=@lecture.pdf;type=application/pdf' \
  -F 'mode=DETAILED_SUMMARY'
```

Поддерживается PDF с текстовым слоем, включая русский текст и несколько страниц.
Поле file остаётся одним; все пять режимов работают как для TXT.
Сервер сверяет расширение с сигнатурой PDF; переименование TXT в PDF или PDF
в TXT не меняет формат содержимого и даёт 415. У TXT дополнительно отклоняются
бинарные данные, включая ZIP/DOCX. MIME части не используется как доказательство формата.

PDFBox 3.0.8 выбран после проверки [официального списка релизов](https://pdfbox.apache.org/download.cgi)
10.11.2026. По умолчанию максимум 50 страниц (PDF_MAX_PAGES), 10 МиБ и 10000 Unicode-кодовых точек текста.
Ожидание извлечения задаётся PDF_TIMEOUT, по умолчанию 10 секунд. Скан без текста, пароль и повреждение
возвращают 422. PDF не обрезается; извлечённый текст проверяется до отправки в LLM.
OCR и восстановление таблиц не выполняются; сложная вёрстка может нарушать порядок слов.

## Ошибки

| Статус | Причина |
|---|---|
| 400 | Невалидный JSON, неверные/лишние поля JSON, пустой текст/файл, неверный режим, нет file, несколько file |
| 413 | Текст длиннее 10000 символов, файл больше 10 МиБ или multipart больше 30 МиБ |
| 415 | Неверный Content-Type запроса или расширение/содержимое файла не соответствует TXT/PDF |
| 422 | PDF без текстового слоя, защищён паролем или повреждён |
| 504 | Разбор PDF не завершился за PDF_TIMEOUT (по умолчанию 10 секунд) |
| 503 | Все PDF-процессы заняты либо не удалось запустить worker |
| 502 | Неполные настройки LLM, неверный ключ, квота, ошибка ответа или таймаут провайдера |

Ошибки возвращаются как `application/problem+json`, например:

```json
{
  "type":"about:blank",
  "title":"Bad Gateway",
  "status":502,
  "detail":"Сервис обработки текста временно недоступен. Повторите запрос позже.",
  "instance":"/api/v1/materials/process"
}
```

Ошибки входных данных отклоняются до обращения к LLM. `detail` описывает причину;
клиенту следует ориентироваться на статус, а не разбирать текст сообщения.
Ошибки превышения лимита возвращают title `Payload Too Large`.

## Адрес сервера

На компьютере: `http://localhost:8080`; стандартный Android-эмулятор:
`http://10.0.2.2:8080`; физический телефон: `http://<IP-компьютера>:8080` в общей сети.
На телефоне `localhost` указывает на телефон. При смене APP_PORT замените порт.

## Разбор и повтор запросов

PDF разбирается отдельным Java-процессом с ограниченным heap. При таймауте
процесс завершается, временные файлы удаляются. По умолчанию одновременно работают
не больше двух worker; занятые слоты дают 503. PDF_TIMEOUT относится к разбору,
а таймаут LLM остаётся отдельным и даёт 502. Повтор POST после ошибки LLM может
вызвать повторную генерацию; после 503 разбора PDF генерация ещё не начиналась.

Набор тестовых PDF и проверки ошибок описаны в
[src/test/resources/pdf/README.md](../../src/test/resources/pdf/README.md).
Результаты проверки пяти учебных материалов — в
[отчёте](../research/PDF_VALIDATION.md).
