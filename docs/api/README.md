# Контракт API

Источник контракта — `openapi.yaml`. Протокол HTTP, данные JSON в UTF-8;
ошибки будущей обработки текста — `application/problem+json` (Problem Details).
Локальный HTTP используется для разработки; перед внешним развёртыванием нужен HTTPS.

## Статус

- `GET /health` и `GET /api/v1/modes` работают.
- `POST /api/v1/text/process` — **черновик для согласования**, код отсутствует;
  реализация относится к задаче #8, которую сейчас не выполняем. Текущий ответ — 404.
- `POST /api/v1/materials/process` — прежняя экспериментальная заглушка 501,
  не входит в согласуемый контракт спринта 1. PDF/DOCX — следующий спринт.
- Авторизация мобильного клиента пока не предусмотрена. Ключ LLM никогда
  не передаётся мобильному клиенту и не включается в примеры запросов.

## Запрос и ответ

Пример для будущего эндпоинта (не проверка действующего LLM):

```bash
curl -i http://localhost:8080/api/v1/text/process \
  -H 'Content-Type: application/json' \
  -d '{"text":"Митохондрии обеспечивают клетку энергией.","mode":"SHORT_SUMMARY"}'
```

В Windows используйте `curl.exe` и файл JSON в UTF-8, например
`curl.exe -H "Content-Type: application/json" --data-binary "@request.json" http://localhost:8080/api/v1/text/process`.
Только `SHORT_SUMMARY` реализуется первым; полный список идентификаторов
и таблица эндпоинтов — в `../wiki/API.md` и `../wiki/Интеграция-с-LLM.md`.

Предложенный лимит — 10000 Unicode-символов в `text`. Пустые/пробельные тексты,
пропущенные поля и неподдерживаемые режимы — 400; превышение длины — 413;
ошибка/таймаут/квота провайдера — 502. Конкретные примеры есть в OpenAPI.
Лимит символов не заменяет токенный лимит провайдера.

## Проверка и изменение

1. Изменить YAML и все затронутые примеры в документации.
2. Выполнить `./mvnw verify`: тест валидирует структуру OpenAPI и разрешение ссылок.
3. Открыть YAML в https://editor.swagger.io/ (File → Import file)
   и проверить отсутствие ошибок. Использовать только файл контракта без секретов.
4. Перед реализацией запросить review минимум у одного участника mobile.
5. После одобрения перенести изменения таблицы API и режимов в GitHub wiki.

Шаги 3–5 не считаются выполненными автоматически после локальной валидации.
Менять адреса, поля, режимы и ограничения без согласования с mobile нельзя.
