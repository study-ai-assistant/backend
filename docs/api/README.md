# API для мобильного приложения

Ветка `feature/server-base` включает реализацию №8 из `feature/8-text-processing`.
Передаём HTTP-запросы; JSON в UTF-8 используется для текста и ответов.
Авторизации мобильного клиента пока нет. LLM-ключ хранится только на сервере.

## Доступные запросы

| Метод | Путь | Запрос | Результат |
|---|---|---|---|
| GET | `/health` | Без тела | 200, `{"status":"ok"}` |
| GET | `/actuator/health` | Без тела | Техническое состояние Spring Boot |
| GET | `/api/v1/modes` | Без тела | Все пять идентификаторов; обработка работает только для SHORT_SUMMARY |
| POST | `/api/v1/text/process` | application/json: text и mode | Краткий конспект через Groq; ошибки 400/413/502 |
| POST | `/api/v1/materials/process` | multipart/form-data: files и mode | Заглушка: непустые файлы → 501, пустые → 400; превышение лимита загрузки → 413 |

**TXT, PDF и DOCX сервер пока не разбирает.** Мобильный клиент может технически
загрузить файл на multipart-маршрут, но результата обработки не получит.
Для работающего сценария передавайте уже готовый текст в JSON.

## Обработка текста

Сервер должен быть запущен с заполненными LLM_PROVIDER=groq, LLM_MODEL,
LLM_BASE_URL и LLM_API_KEY. Изменения .env требуют перезапуска сервера.
Подробные настройки — в README и [интеграции с LLM](../wiki/Интеграция-с-LLM.md).

```bash
curl -i --max-time 90 http://localhost:8080/api/v1/text/process \
  -H 'Content-Type: application/json' \
  --data-raw '{"text":"Митохондрии обеспечивают клетку энергией.","mode":"SHORT_SUMMARY"}'
```

Пример ответа 200 (формулировка модели может отличаться):

```json
{"mode":"SHORT_SUMMARY","result":"Митохондрии снабжают клетку энергией."}
```

Результат — строка, не массив и не объект с разделами.

### Правила JSON

- Ровно два поля: `text` и `mode`; лишние и отсутствующие поля дают 400.
- `text` — строка, содержит хотя бы один символ, соответствующий проверке `\S`.
  Пустая строка и строка из обычных пробелов/переносов дают 400.
- Максимум 10000 Unicode-кодовых точек. Emoji считается по кодовым точкам,
  а не по визуальным символам и не по размеру JSON в байтах.
- `mode` — строго `SHORT_SUMMARY`, с указанным регистром.
  Другие режимы из списка `/api/v1/modes` пока дают 400.
- Внутри строки перенос кодируется как `\n`, кавычка как `\"`.
  Не вставляйте буквальный Enter между кавычками JSON-строки.
  Мобильному клиенту следует использовать JSON-сериализатор библиотеки.

### Длинный текст и абзацы

Сохраните текст в `material.txt` (UTF-8), затем в Linux/macOS создайте JSON:

```bash
python3 - <<'PYTHON'
import json
from pathlib import Path
payload = {
    "text": Path("material.txt").read_text(encoding="utf-8"),
    "mode": "SHORT_SUMMARY"
}
Path("request.json").write_text(json.dumps(payload, ensure_ascii=False), encoding="utf-8")
PYTHON
curl -i --max-time 90 http://localhost:8080/api/v1/text/process \
  -H 'Content-Type: application/json' --data-binary @request.json
```

Это отправка JSON с текстом, **не загрузка документа серверному парсеру**.
Готовый небольшой пример: `docs/api/examples/short-summary-request.json`.
Из корня проекта:

```bash
curl -i --max-time 90 http://localhost:8080/api/v1/text/process \
  -H 'Content-Type: application/json' \
  --data-binary @docs/api/examples/short-summary-request.json
```

Windows PowerShell, тот же файл:

```powershell
curl.exe -i --max-time 90 http://localhost:8080/api/v1/text/process -H "Content-Type: application/json" --data-binary "@docs/api/examples/short-summary-request.json"
```

### Ошибки и ожидание

| HTTP | Причина | Что делать клиенту |
|---|---|---|
| 400 | Неверный JSON, поля, тип данных, пустой текст или режим | Исправить запрос |
| 413 | text длиннее 10000 кодовых точек | Сократить текст |
| 415 | Content-Type не application/json | Передать правильный Content-Type |
| 502 | Нет настроек Groq, неверный ключ, сбой сети/провайдера, квота, таймаут или пустой ответ модели | Показать ошибку; проверить настройки/квоту на сервере, повторить позже |

Для 400/413/502 обработчик возвращает application/problem+json:

```json
{"type":"about:blank","title":"Bad Gateway","status":502,"detail":"Сервис обработки текста временно недоступен. Повторите запрос позже.","instance":"/api/v1/text/process"}
```

415 обрабатывается Spring. Не рассчитывайте, что его тело обязательно имеет
все поля схемы ошибок контроллера. Внешние подробности и ключ клиенту не передаются.
Подключение к Groq ограничено 5 секундами, ожидание результата — 60 секундами.
На мобильном клиенте рекомендуется таймаут 90 секунд.
Повтор POST может повторно потратить квоту: бесконечные автоматические повторы не нужны.
Предварительного подсчёта токенов и очереди запросов пока нет; лимит символов
не гарантирует, что запрос помещается в текущую квоту провайдера.

## Подключение с телефона

Компьютер: http://localhost:8080; стандартный Android-эмулятор:
http://10.0.2.2:8080; телефон в общей локальной сети:
http://<IP-компьютера>:8080. На телефоне localhost — сам телефон.
Сначала проверьте /health. Нужны доступ к порту и INTERNET-разрешение Android;
для локального HTTP при необходимости настройте debug-политику приложения.

## Контракт и проверка

Полная схема — [openapi.yaml](openapi.yaml). Политика изменения контракта:
изменять примеры вместе со схемами, согласовывать с mobile, затем обновлять wiki.
Реализация не означает автоматического одобрения контракта командой mobile.

`./mvnw verify` проверяет код, HTTP-сценарии, клиент Groq на локальной имитации API
и структуру OpenAPI. Реальные LLM-ключи для тестов не нужны.
Для ручной проверки Groq используйте небольшой учебный текст и собственный ключ.
Веб-проверка: открыть YAML в https://editor.swagger.io/ без секретов.
