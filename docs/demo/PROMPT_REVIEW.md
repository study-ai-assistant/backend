# Замечания по промптам для Ярослава

Подготовлено для передачи. Сообщение участнику ещё не отправлялось.
Исходные ответы сохранены в results/, замеры — в отчёте
[LONG_MATERIAL_VALIDATION.md](../research/LONG_MATERIAL_VALIDATION.md).

1. Первоначального completion=800 не хватило третьей части четырёхчастного
   материала даже в SHORT_SUMMARY: Groq сообщил finish_reason=length.
   Теперь задано 1600 на часть, 2400 на объединение и компактный промежуточный
   ответ до 150 слов. Обрезанный ответ считается ошибкой, не выдаётся за итог.
2. В SIMPLE_EXPLANATION модель иногда оставляет **Markdown**, хотя инструкция
   запрещает его. Сервер убирает оформление отдельно; тесты сохраняют x**2,
   умножение и Unicode. Одной просьбы в system prompt для формата недостаточно.
3. Вопросы могут проверять одну идею разными словами. В 2-parts встречалась
   пара про отдельный учёт ожидания, в 4-parts — про данные для повторной попытки.
   Поиск точного совпадения строк такие пары не обнаруживает. В объединение
   добавлена попарная проверка по ожидаемому ответу и правило одной темы.
   Для длинного материала выбирается не больше шести разных вопросов: это
   укладывается в контракт «не больше десяти» и уменьшает искусственные повторы.
4. Вопрос «Какие два типа отказа необходимо назвать в упражнении раздела 1?»
   не имеет готового ответа в источнике: источник только просит их назвать.
   Уточнено, что подтверждающий фрагмент должен содержать ответ, а не поручение
   найти его. Вопросы без ответа исключаются на обоих этапах.
5. Материал на две части содержит намеренно похожие синтетические случаи.
   Он полезен для проверки повторов, но для живого показа лучше русская лекция
   с разными темами. Полная матрица входов и режимов есть в results/long.

Отдельное замечание по терминам: в четырёхчастном примере встречаются близкие
понятия «ограничение запросов», «лимит» и «квота», а также неудачное название
«очередь ограничений». Точных повторов строк нет, но смысловой отбор требует
ручного review. Эти замечания сохранены как результат проверки качества;
автоматическое отсутствие дублей по строкам не доказывает отсутствие синонимов.

Повторные вопросы после уточнения промптов сохраняются в results/recheck.
Это ручная оценка конкретных ответов, не гарантия качества на любом материале.
