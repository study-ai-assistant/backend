# Материалы для показа

Для запуска сервера и подключения телефона используйте [инструкцию записи](RECORDING.md).
Свежие результаты проверки — в [чек-листе API](../qa/API_CHECKLIST.md).

Это собственные учебные примеры проекта, без персональных данных и скопированных
чужих лекций. Условия использования текстов — в LICENSE.txt, лицензия шрифта —
в FONT-LICENSE.txt. Генератор: tools/demo/generate_materials.py (нужен reportlab).
PDF проверены после рендеринга: короткий документ на одной странице, длинный на шести.

| Файл | Как показывать |
|---|---|
| short-text.txt | Вставить текст в приложение, старый JSON-маршрут |
| short-file.txt | Загрузить как TXT, старый маршрут материалов |
| study-notes.pdf | Короткий PDF с русским текстовым слоем, старый маршрут материалов |
| long-lecture.txt | Четыре раздела лекции об алгоритмах, очередях и проверках, новый API заданий |
| long-lecture.pdf | Расширенная лекция из шести разделов в PDF, новый API заданий |
| benchmark-2-parts.txt | Англоязычные учебные случаи для замера на двух частях |

Набор предназначен для проверки всех пяти режимов, а не только краткого конспекта.
Исходные ответы и точные времена находятся в results/long и results/demo.
Первоначальная проверка с меньшим запасом генерации сохранена в results/calibration.
В examples/ лежат версии для отображения: к ним применён тот же LlmOutputFormatter,
что используется сервером, без ручного изменения содержания. Для вопросов
предпочтение отдаётся более позднему повтору из results/recheck.
Инструмент PrepareExamples.java проверяет размер материалов и обновляет examples/
без вызовов LLM. Формальные проверки выполняет tools/demo/analyze_results.py.
Ответы — примеры отдельного запуска, повторный вызов может сформулировать иначе.

## Запуск

Поднять backend по главному README. Для реального ответа нужны настройки Groq
в .env; ключ не передаётся в команды ниже. Короткий TXT:

```bash
curl -i --max-time 90 http://localhost:8080/api/v1/materials/process \
  -F 'file=@docs/demo/short-file.txt;type=text/plain' \
  -F 'mode=SHORT_SUMMARY'
```

Длинный PDF:

```bash
curl -i --max-time 30 http://localhost:8080/api/v1/jobs/materials \
  -F 'file=@docs/demo/long-lecture.pdf;type=application/pdf' \
  -F 'mode=KEY_TERMS'
curl -i http://localhost:8080/api/v1/jobs/ID_ИЗ_ОТВЕТА
```

Второй запрос повторять раз в три секунды до SUCCEEDED/FAILED. Готовый ответ
в result, ошибка в error. Долгое состояние RUNNING во время ожидания квоты
не означает зависание. Стадия MERGE идёт после завершения всех частей.
Не выполняйте несколько демо подряд одновременно с замерами: у организации
Groq общая квота, она влияет на время ожидания.

## Воспроизведение замеров

Скрипт обращается к работающему backend по HTTP, не читает .env и ключ.
Он выполняет реальные вызовы через сервер и расходует квоту Groq.
Обычный ./mvnw verify этот скрипт не запускает.

```bash
python3 tools/demo/run_benchmark.py --base-url http://localhost:8080 \
  --suite long --output /tmp/study-long-run
python3 tools/demo/run_benchmark.py --base-url http://localhost:8080 \
  --suite demo --output /tmp/study-demo-run
```

Длинный набор: 2 части (JSON), 4 части (длинный TXT как JSON),
6 частей (PDF) во всех режимах.
Короткий: текст, TXT и PDF во всех режимах. Скрипт сохраняет ответы,
прогресс, elapsed time и доступные usage в measurements.json. У короткого
синхронного ответа нет usage в публичном контракте, там значения null.
При ошибке скрипт останавливается. Сначала проверьте причину; после разового
сетевого сбоя дождитесь восстановления связи и повторите незавершённые сценарии.
Уже успешные пары материал/режим в том же output повторно не вызываются.
Не считайте повторно затраченные токены бесплатными при расчёте дневного бюджета.

Подробный отчёт по времени, токенам, качеству и рекомендациям для показа:
[LONG_MATERIAL_VALIDATION.md](../research/LONG_MATERIAL_VALIDATION.md).
Для mobile подготовлен [чек-лист](MOBILE_CHECKLIST.md). Передача набора и
проверка на телефоне выполняются отдельно; готовность файлов их не заменяет.

## Результаты проверок

18 ноября проверены длинные материалы во всех режимах и 11 из 15 коротких
сочетаний. Четыре режима короткого PDF тогда остались неподтверждёнными из-за
дневной квоты; неудачные попытки сохранены в исходных измерениях.

В `feature/56-demo-prompts` добавлены уточнения промптов и повторные ответы в
`results/final-prompt-check`. 26 ноября короткие JSON, TXT и PDF снова проверены
через Docker и Groq: все 15 сочетаний прошли. Один сетевой таймаут TXT сохранён
в журнале; повтор завершился успешно. Новые ответы не подменяют исторические.

Полная текущая матрица длинных и коротких материалов, время, сбои и команды
повторного запуска находятся в [чек-листе API](../qa/API_CHECKLIST.md).
Для полного набора используется `--suite acceptance` с новой output-папкой.
Уже успешные пары скрипт пропускает; перед продолжением выдерживает минутную паузу.
Не расходуйте весь дневной бюджет перед записью: порядок сцен и запас квоты
описаны в [инструкции записи](RECORDING.md).

При изменении входных материалов используйте новую output-папку, чтобы не
смешивать старые ответы с новым содержимым. Перезапуск сервера сбрасывает
локальный счётчик, но не обновляет квоту Groq; не используйте его для обхода лимита.
