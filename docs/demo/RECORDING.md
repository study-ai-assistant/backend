# Запуск сервера для записи видео

Проверяйте сервер заранее, а перед записью выполняйте только выбранные сцены.
Полный прогон всех режимов расходует заметную часть бесплатной квоты.

## Чистый запуск через Docker

Нужны Git, работающий Docker Engine / Docker Desktop с Compose и доступ к интернету.
JDK и Maven на ноутбуке для этого способа не нужны.

```bash
git clone https://github.com/study-ai-assistant/backend.git
cd backend
cp .env.example .env
```

Для проверки изменений до принятия PR выберите опубликованную ветку командой
`git switch 59_61`. Пока ветка существует только локально, в свежем клоне
с GitHub её не будет; сначала потребуется её публикация. Проверка 26 ноября
выполнена из отдельного локального клона с тем же кодом сервера.

В PowerShell последнюю команду замените на `Copy-Item .env.example .env`.
Откройте `.env` в редакторе и заполните четыре значения:

```properties
LLM_PROVIDER=groq
LLM_MODEL=openai/gpt-oss-120b
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_API_KEY=
APP_PORT=8080
```

Если Backend уже работает в IDEA на 8080, остановите его перед этим запуском
или задайте другой свободный `APP_PORT` и используйте его в адресах ниже.

После `LLM_API_KEY=` вставьте свой ключ без кавычек. Не присылайте `.env` другим
участникам и не показывайте его в видео. Существующий файл не перезаписывайте.

```bash
docker compose up --build -d --wait --wait-timeout 180
docker compose ps
curl --fail http://localhost:8080/health
curl --fail http://localhost:8080/api/v1/modes
```

В PowerShell используйте `curl.exe`. Ожидаются healthy, `{"status":"ok"}` и
список пяти режимов. Таймаут 180 секунд относится к запуску контейнера после
сборки. Первый запуск также скачивает образы, Maven и зависимости: время зависит
от сети. Если сборка не уложилась в 10 минут, сохраните время и этап остановки;
не отмечайте проверку успешной только потому, что контейнер позже запустился.

При исправлении Java-кода повторите команду с `--build`.
При изменении только `.env`: `docker compose up -d --force-recreate --wait`.
Остановка: `docker compose down`. Задания при остановке теряются.

## Подключение телефона

1. Подключите ноутбук и телефон к одному обычному Wi-Fi, без изоляции клиентов
   гостевой сети. На время проверки отключите VPN, если он перехватывает локальную сеть.
2. Найдите Wi-Fi IPv4 ноутбука: Windows — `ipconfig`, Linux — `ip -4 address`,
   macOS — настройки Wi-Fi → сведения о сети → TCP/IP.
   Нужен адрес Wi-Fi адаптера, например `192.168.1.10`, а не Docker, VPN или `127.0.0.1`.
3. На ноутбуке откройте `http://<IP>:8080/health`, затем тот же адрес в браузере телефона.
   Должно появиться `{"status":"ok"}`.
4. В приложении задайте базовый адрес `http://<IP>:8080` без пути `/health`.
   На телефоне `localhost` указывает на телефон. Для Android-эмулятора — `http://10.0.2.2:8080`.
5. Если браузер телефона не подключается, проверьте порт в `.env`, Wi-Fi и правило
   входящего TCP-порта в межсетевом экране. Если нужно правило, ограничьте его
   доверенной локальной сетью; отключать межсетевой экран целиком не нужно.
6. Если браузер подключается, а приложение — нет, проверьте базовый URL,
   `android.permission.INTERNET` и разрешение локального HTTP в debug-сборке Android.

У API пока нет авторизации. Для записи используйте доверенную локальную сеть;
проброс портов на роутере и публичный туннель не требуются.

## План записи и квота

Лимиты одного экземпляра backend: 8 000 токенов и 30 вызовов в минуту,
200 000 токенов и 1 000 вызовов за скользящие 24 часа. У аккаунта Groq могут
быть другие ограничения и общий расход других разработчиков. Перед записью
проверьте Limits / Usage в кабинете аккаунта и договоритесь не запускать параллельно
нагрузочные прогоны с тем же аккаунтом. Новый ключ того же аккаунта не гарантирует новую квоту.

Для одного дубля достаточно:

| Сцена | Материал и действие | Вызовы Groq |
|---|---|---:|
| Проверка связи | `/health`, `/api/v1/modes` | 0 |
| Режимы | `short-text.txt` как JSON, по одному запросу на каждый из пяти режимов | 5 |
| TXT | `short-file.txt`, один выбранный режим | 1 |
| PDF | `study-notes.pdf`, один выбранный режим | 1 |
| Прогресс | `long-lecture.txt` через `/api/v1/jobs/materials`, один режим | 5 |
| Ошибка | пустой TXT или неподдерживаемый DOCX | 0 |

Для этого набора планируйте **до 40 000 токенов на дубль**, а перед репетицией
и записью оставьте хотя бы **100 000 свободных токенов**. Это запас для указанных
небольших материалов, не обещание для любых файлов. Если вместо длинного TXT
берёте шестичастный PDF, будет семь вызовов; оставьте дополнительный запас.
Сохранённые ответы в `docs/demo/results/final-prompt-check` помогают заранее
подобрать сцены, но показывать их как новую живую генерацию нельзя.

Короткие запросы отправляйте по одному. После каждых трёх выдерживайте 61 секунду,
а перед длинным материалом — ещё 61 секунду после последнего короткого запроса.
Фоновая очередь сама ждёт минутную квоту; короткий маршрут при занятой квоте
может сразу вернуть 502. Опрос статуса раз в три секунды не расходует токены.
Длинная генерация может занять несколько минут — учитывайте это при записи.

Если нужна репетиция с терминала вместо приложения, скрипт отправит именно
указанный набор: пять режимов JSON, по одному TXT/PDF и длинный TXT.
Он расходует реальную квоту:

```bash
python3 tools/demo/run_benchmark.py --base-url http://localhost:8080 --suite recording --output target/recording-1
```

Для нового дубля выбирайте новую output-папку. При повторе с той же папкой
успешные сочетания пропускаются; скрипт продолжает незавершённые.

Не запускайте полный `--suite acceptance` перед самым видео: он проверяет 25
генераций. Он нужен для приёмки, а не для каждой репетиции.
Не нажимайте отправку повторно, пока исходное задание выполняется.
При 502 с сообщением о лимите остановите генерацию и проверьте квоту.
Перезапуск очищает локальный счётчик в памяти, **но не квоту Groq**. Окно квоты
не обязано обнуляться в полночь. Если дневной бюджет уже использован,
дождитесь восстановления, не повышайте настройки только ради обхода ошибки.

## Перед началом записи

- Контейнер healthy, ноутбук подключён к питанию, сон на время записи не сработает.
- На телефоне открывается `/health`, в приложении выбран правильный адрес.
- Материалы заранее скопированы на телефон, TXT и PDF открываются.
- Ключ и `.env` не попадают в кадр. Не показывайте вывод `docker compose config`
  или `docker inspect`: там может быть ключ.
- Квоты достаточно на репетицию и дубль; другие участники не расходуют её одновременно.
- Проверены все сцены, включая ошибку и ожидание фонового задания.
- Содержание ответов сверено с исходниками; известные замечания — в
  [QUALITY_NOTES.md](../qa/QUALITY_NOTES.md).

## Подтверждение вторым участником

Другой участник должен пройти инструкцию на своём чистом клоне и записать:

```text
Имя / аккаунт:
Дата, ОС, версия Docker Compose:
Ветка и git rev-parse HEAD:
Время от запуска docker compose до healthy:
/health на ноутбуке:
/health в браузере телефона:
JSON / TXT / PDF / длинный материал в приложении:
Проблемы и что пришлось сделать дополнительно:
```

Пока такой проверки нет, критерии телефона и второго участника остаются открытыми.
