Инвариант — это условие, которое должно оставаться истинным до и после любой операции.  
Перед выполнением запроса система проверяет предусловия:  

* входные данные находятся в допустимом диапазоне (например, количество запросов ≤ лимита, идентификаторы уникальны, количество товаров ≥ 0);  
* требуемый ресурс (квота, память) доступен;  
* текущий счётчик активных заданий < лимита (например, 30 или 40 запросов в минуту).  

Если хотя бы одно из этих условий нарушено, запрос отклоняется и никакие изменения состояния не сохраняются.

Успешный исход  
При выполнении всех предусловий сервер возвращает код успеха (200 / 202 / прочие «успешные» статусы). В ответе может присутствовать:

* подтверждение завершения операции,  
* идентификатор задания и прогресс = 100 % (для асинхронных задач),  
* заголовок Location со ссылкой для последующего опроса статуса,  
* результат выполнения (например, найденный элемент).

Все ресурсы освобождаются, состояние остаётся консистентным.

Отказы  

1. Превышение лимита (квоты) – код 429 Too Many Requests.  
   *Тело ответа*: сообщение о превышении лимита, текущий счётчик и максимум.  
   *Заголовок*: `Retry‑After` – время, через которое можно повторить запрос.  

2. Неправильный ввод – код 400 Bad Request.  
   *Тело ответа*: полученное значение, ожидаемый диапазон, перечень недостающих или некорректных полей.  

3. Ошибка выполнения – код 500 Internal Server Error (или иной серверный код).  
   *Тело ответа*: описание места ошибки (например, «ошибка на шаге 4»).  

Информация для повторной попытки всегда включает:

* тип ошибки (лимит / валидация / внутренняя ошибка);  
* точные параметры, которые нарушены (например, «запрос = 24, максимум = 20»);  
* при 429 — значение `Retry‑After` (секунды или дата);  
* при 400 — правильный диапазон или пример корректного значения;  
* при 500 — указание, какие части нужно исправить, если ошибка связана с вводом.  

Эти данные позволяют клиенту скорректировать запрос (уменьшить пакет, подождать, исправить параметры) и безопасно повторить его без раскрытия конфиденциальных настроек.

Тестирование  

* Три базовых набора входов: пустой, один элемент, полный набор.  
* Граничные варианты: максимум, максимум − 1, максимум + 1.  
* При ошибке на любом этапе проверяется, что результат не создан и все ресурсы освобождены.  

Замечание: наблюдение (полученный ответ) отделяется от вывода (утверждение о безошибочности всей системы).  

Таким образом, последовательность проверки предусловий → выполнение → возврат кода успеха или детального отказа и предоставление клиенту всей необходимой информации обеспечивает корректность, предсказуемость и возможность безопасного повторения запросов.
