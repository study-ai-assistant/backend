Sequential processing — последовательная обработка задач в порядке их поступления, при которой каждая задача начинает выполняться только после завершения предыдущей  

Test design — разработка теста, фиксирующего входные данные, проверяющего завершённую работу и фиксирующего явный отказ (clear failure) вместо частичного успеха  

Service (служба) — программный компонент, принимающий набор задач и обрабатывающий их последовательно в соответствии с порядком поступления и ограничениями ресурсов  

Task (задание) — отдельная единица работы, требующая фиксированного времени выполнения  

Arrival order (порядок поступления) — правило, определяющее последовательность обслуживания задач в том порядке, в котором они пришли в очередь  

Work alone time — время, необходимое только для выполнения всех задач без учёта ожидания в очереди и задержек квот провайдера (рассчитывается как количество задач, умноженное на время выполнения одной задачи)  

Queue waiting (ожидание в очереди) — задержка, возникающая из‑за ожидания задачи в очереди перед началом её обработки, обусловленная ограничениями пропускной способности сервиса  

Provider quota delays (задержка из‑за квоты провайдера) — задержки, связанные с исчерпанием выделенных провайдером ресурсов, которые могут приостанавливать выполнение задач  

Synthetic data (синтетические данные) — искусственно созданные данные, используемые в примерах тестов и не отражающие реальную производительность в продакшн‑среде  

Production speed (скорость в продакшн) — реальная скорость выполнения задач в рабочей (продакшн) среде, которую примеры тестов не предсказывают  

Clear failure (явный отказ) — результат теста, когда проверка обнаруживает несоответствие ожидаемому результату, то есть сервис не завершил все ожидаемые задачи  

Partial success (частичный успех) — ситуация, когда часть задач выполнена корректно, а остальные нет; в данном подходе считается недопустимым  

HTTP‑контракт — формальное описание требований к запросам и ответам между клиентом и сервисом, включающее методы, заголовки, коды статуса и ограничения по времени выполнения  

Resource limit (ограничение ресурса) — предельно допустимое количество или объём используемых сервисом ресурсов (например, число одновременных задач, время процессинга), превышение которых приводит к отказу или замедлению обслуживания  

Test records input (тест фиксирует ввод) — процесс сохранения переданных в сервис заданий для последующего анализа результатов  

Checks completed work (проверка выполненной работы) — этап верификации, когда сравнивается ожидаемый набор завершённых задач с фактическим результатом выполнения.
