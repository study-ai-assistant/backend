Алгоритм – конечная последовательность понятных исполнителю шагов, предназначенных для решения конкретной задачи. Один и тот же результат может быть получен разными алгоритмами, однако они могут различаться по времени выполнения и расходу памяти.

Линейный поиск
- Последовательный просмотр элементов массива.
- Работает как в отсортированном, так и в неотсортированном массиве.
- В худшем случае проверяется каждый из n элементов → O(n).

Бинарный поиск
- Требует предварительно отсортированный массив.
- После каждого сравнения отбрасывается половина оставшегося диапазона.
- Число шагов растёт пропорционально логарифму n → O(log n).

Выбор алгоритма должен учитывать не только асимптотическую сложность, но и условия применимости. Для небольших массивов линейный поиск может быть предпочтительнее, несмотря на более высокую асимптотическую оценку.

Тестирование программ

*Модульный тест*
- Проверяет небольшую часть программы изолированно от внешних систем.

*Заглушка (stub)*
- Замещает внешнюю зависимость предсказуемым поведением.
- Пример: вместо вызова языковой модели возвращает заранее заданный ответ.

*Интеграционный тест*
- Оценивает совместную работу нескольких компонентов системы.

*HTTP‑тест*
- Отправляет реальный запрос к локальному серверу.
- Проверяет код ответа, заголовки и тело.

Сценарии тестов:
- Положительный – подтверждает корректную работу запроса при правильных данных.
- Отрицательный – проверяет появление понятной ошибки при неверных данных.

Тесты должны быть воспроизводимыми: их результат не должен зависеть от доступности внешних API, секретных ключей и других переменных окружения.

Дополнительная проверка с помощью `curl` может использоваться совместно с автоматическими тестами, но не заменяет их.

*Учебный пример проекта* – использование синтетических данных для демонстрации описанных подходов.
