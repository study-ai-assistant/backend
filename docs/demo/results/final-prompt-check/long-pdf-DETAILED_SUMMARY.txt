Часть 1. Данные и инварианты
Инвариант — условие, сохраняемое до и после операции (например, уникальные идентификаторы, неотрицательное количество). Проверка инварианта относится к границе изменения данных; при нарушении операция завершается ошибкой без частичного изменения состояния. Пустая коллекция допускается, если контракт её не запрещает. Размер входа ограничивается, чтобы избежать дорогих вычислений (пример — 10 запросов/мин; лишние 2 запроса вызывают отказ или постановку в очередь). Тесты используют наборы: пустой, один элемент, полный. При ошибке на конкретном шаге проверяется отсутствие результата и освобождение ресурсов. Время обработки части = 3 с, четырёх частей = 12 с (без учёта квот). На ревью сравниваются вход, контракт и результат; названия режима должны совпадать, числовые значения нельзя округлять так, чтобы менялся смысл. При повторных запросах клиент получает код отказа без содержимого документа или секретов. Граничные проверки: максимум, максимум − 1, максимум + 1. При одновременном чтении клиенты видят согласованные поля; после перезапуска память очищается, требуется повторная отправка.

Линейный поиск — последовательные сравнения; худший случай = n сравнений. Бинарный поиск работает только на отсортированном массиве; без сортировки результат некорректен. Оценка сложности O(n) используется в учебных примерах.

Часть 2. Очереди и фоновые задания
Очередь хранит задания в порядке поступления; один исполнитель берёт следующее только после завершения текущего. Клиент получает идентификатор задания и отдельный запрос статуса. Состояния задания: в очереди, выполняется, готово, ошибка. Прогресс измеряется количеством завершённых частей, а не временем. При ошибке части нельзя выдавать неполный итоговый ответ. Задания имеют срок жизни; после истечения периода их временное хранение удаляется.

Пример: сервер принимает 36 запросов в минуту, ограничение 30; лишние 6 запросов отклоняются с сообщением или помещаются в ограниченную очередь.

Тесты используют наборы из 60 элементов (пустой, один, полный). При ошибке на шаге 4 проверяется отсутствие итогового результата и корректное освобождение ресурсов. Идентификатор задания, статус и код ошибки обязаны быть одинаковыми при повторных запросах. Сообщения об ошибке не содержат содержимого документа и секретных настроек.

Часть 3. Освобождение ресурсов и HTTP‑ошибки
Вызов функции не доказывает корректность данных; требуется проверка входа (типы, диапазоны) до начала работы. Успешный исход — завершённая часть с итогом. Отказ 1 — превышение лимита (одинаковый код при повторе); отказ 2 — неверный запрос (400). При повторной попытке клиент получает код ошибки, описание нарушения и рекомендацию (интервал повторения, необходимые параметры). При перезапуске память очищается, возможна повторная отправка.

HTTP‑методы: GET — чтение, POST — создание/запуск действия. 202 — задание принято, результат будет готов позже; клиент опрашивает URL из заголовка Location. 400 — неверный запрос; 413 — превышение размера; 404 — ресурс не найден. Сбой внешнего сервиса требует отдельного понятного сообщения; повторный POST может создать дублирование. При превышении квоты (например, 48 запросов/мин при лимите 40) сервер обязан вернуть отказ либо поставить запросы в очередь, а не терять их. Тесты аналогичны предыдущим; при ошибке на шаге 5 проверяется отсутствие результата и освобождение ресурсов.

Часть 4. Дополнительные условия
Перед запуском сравнивают размер материала для экспериментов. Успешный исход — сервер возвращает итоговый результат и подтверждает выполнение конкретного запроса. Отказы: 1) превышение лимита — одинаковый код при повторе; 2) несогласованные поля состояния (число завершённых частей > общее число). Для повторной попытки клиент получает код ошибки, текущий номер части, общий размер материала, сведения о том, что после перезапуска память очищается. Граничные проверки: максимум, максимум − 1, максимум + 1; материал должен пройти полностью. При одновременном чтении два клиента видят согласованные поля. Наблюдения (метрики) отделяются от вывода (оценка качества).

Часть 5. Тестирование и измерения
Перед тестом задают известные входные данные и ожидаемый результат; используют заглушку внешнего сервиса. Успешный исход — корректный замер с правильным порядком выполнения и обновлением прогресса. Отказы: 1) превышение квоты — сообщение об ошибке или постановка в очередь; 2) ошибка на шаге 6 — отсутствие итогового результата и освобождение ресурсов. При повторной попытке клиент получает код ошибки, причину отказа, текущий статус очереди, требуемые параметры запроса. Граничные проверки: пустой набор, один элемент, полный набор; сравнение входа, контракта и наблюдаемого результата; точные числовые значения без округления. Все измерения (пиковая память, число вызовов, длительность) фиксируются отдельно и не заменяют оценку качества ответа.

Часть 6. Безопасность и ресурсы
Секретный ключ хранится только на сервере; не попадает в приложение, репозиторий, журналы. В сообщениях об ошибке внешний ответ не копируется целиком. Ограничения: размер файла (память), таймаут (длительность), лимит количества заданий. При превышении лимита (пример — 72 запроса/мин, лимит 60) сервер должен отказать или поставить в очередь, а не терять запросы. Временные файлы удаляются после завершения или ошибки. Граничные тесты: пустой вход, один элемент, полный набор; при ошибке на шаге 7 проверяется отсутствие результата и освобождение ресурсов. Время обработки части (пример 8 сек) суммируется по частям; ожидание квоты и объединение считаются отдельно. Проверяется совпадение названия режима в запросе и ответе, точные числовые значения без округления, отсутствие догадок при отсутствии определения. Перед началом работы проверяется лимит ресурсов. Успешный исход — корректный результат; отказы — превышение лимита, ошибка доступа к секрету. При повторной попытке клиент получает код отказа и информацию о требуемом действии, без раскрытия содержимого документа или секретных настроек.

Часть 7. Пример 6 (согласованные поля)
1. Согласованные поля: число завершённых частей ≤ общее число частей; успешное задание → наличие итоговой части.
2. Перезапуск приводит к очистке памяти; клиент может потребовать повторную отправку данных. Свойства используемого временного хранилища (автосброс) должны быть описаны заранее.
3. Успешный ответ сервера подтверждает выполнение конкретного запроса, но не гарантирует отсутствие ошибок в других документах.
4. Для содержательной проверки необходимо сравнить определения и вычисления с исходным материалом, зафиксировать ограничения и способы их воспроизведения.
