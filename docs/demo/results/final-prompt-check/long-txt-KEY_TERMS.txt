Инвариант — условие, которое программа обязана сохранять как до, так и после выполнения операции.

Граница изменения данных — момент, в котором проверяется соблюдение инварианта; при нарушении операция завершается ошибкой без частичного изменения состояния.

Пустая коллекция — допустимый вход, если контракт системы явно не запрещает её использование.

Ограничение входа — предельный размер или количество запросов, при превышении которого система должна отказать или поместить запросы в ограниченную очередь.

Контракт (Contract) — формальное описание требований к входным данным и ожидаемому результату, с которым сравнивается наблюдаемый результат при проверке.

Код отказа — одинаковый идентификатор ошибки, возвращаемый при повторных превышениях лимита.

Граничные значения — набор тестовых входов, включающий допустимый максимум, значение на единицу меньше и значение на единицу больше, используемый для проверки корректности ограничения.

Согласованные поля — набор данных, которые одновременно читающие клиенты должны видеть одинаковыми (например, число завершённых частей не превышает общее число частей).

Линейный поиск — последовательное сравнение элементов с образцом; в худшем случае для n элементов требуется n сравнений.

Бинарный поиск — поиск в отсортированном диапазоне, который каждый шаг делит пополам; корректность гарантируется только при предварительной сортировке.

Оценка O(n) — асимптотическое описание роста затрат при увеличении входных данных, не являющееся измерением реального времени.

Ограничение запросов — максимальное количество запросов, которое сервер может обработать за заданный период; превышение должно приводить к отказу или постановке в очередь.

Квота — ограничение количества запросов или ресурсов за фиксированный интервал (например, 30 запросов в минуту); её превышение приводит к отказу или постановке в ограниченную очередь, ожидание учитывается отдельно от основной длительности.

Временное хранение — механизм, сохраняющий состояние между запросами до перезапуска; после перезапуска память очищается, поэтому клиенту может потребоваться повторная отправка (данные удаляются после заданного срока).

Очередь — структура, сохраняющая задания в порядке их поступления.

Исполнитель — процесс, который берёт следующее задание из очереди только после завершения текущего.

Статус задания — информация, которую клиент получает по идентификатору задания; может принимать состояния «в очереди», «выполняется», «готово», «ошибка».

Прогресс — показатель завершённых частей задания, а не оценка оставшегося времени.

Ошибка — состояние, при котором части задания не могут быть выданы как окончательный результат; сервер должен сообщить отказ или поместить запрос в ограниченную очередь.

GET — метод HTTP, используемый для чтения текущего состояния ресурса.

POST — метод HTTP, создающий ресурс или инициирующий действие.

202 Accepted — код ответа, означающий, что запрос принят, но результат ещё не готов; клиент должен опрашивать указанный в заголовке Location адрес.

Location — заголовок ответа, содержащий URL, по которому клиент должен повторно запрашивать статус выполнения.

400 Bad Request — ошибка, указывающая на некорректный синтаксис или параметры запроса.

413 Payload Too Large — ошибка, указывающая, что размер передаваемых данных превышает допустимый предел.

404 Not Found — ошибка, указывающая, что запрашиваемый ресурс отсутствует.

Ограниченная очередь — механизм, в который сервер помещает запросы, превышающие текущий лимит, вместо их тихой потери.

Перезапуск — событие, после которого временно сохранённые данные (например, память) очищаются, и клиент может потребовать повторную отправку запроса.

Наблюдение — проверка фактического поведения системы (например, совпадение полей) без вывода обобщающих заключений.

Вывод — заключение, сделанное на основе наблюдения, требующее подтверждения дополнительными проверками.
