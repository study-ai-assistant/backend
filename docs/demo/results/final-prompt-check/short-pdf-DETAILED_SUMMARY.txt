Алгоритм – конечная последовательность понятных исполнителю шагов, обеспечивающих решение задачи.
Один и тот же результат может быть достигнут разными алгоритмами, при этом различаются время выполнения и расход памяти.

Линейный поиск
- Последовательный просмотр элементов массива.
- Работает как в отсортированном, так и в неотсортированном массиве.
- В худшем случае проверяется каждый из n элементов → O(n).

Бинарный поиск
- Требует предварительно отсортированный массив.
- После каждого сравнения отбрасывается половина оставшегося диапазона.
- Число шагов пропорционально log₂ n → O(log n).

Выбор алгоритма
- Необходимо проверять условия применимости (наличие сортировки, размер данных).
- Для небольших массивов линейный поиск может быть предпочтительнее, несмотря на более высокую асимптотическую сложность.

Тестирование программ

Модульный тест
- Проверяет небольшую часть кода изолированно от внешних систем.

Заглушка (stub)
- Замещает внешнюю зависимость предсказуемым поведением (например, вместо вызова модели возвращает фиксированный ответ).

Интеграционный тест
- Оценивает совместную работу нескольких компонентов системы.

HTTP‑тест
- Отправляет реальный запрос локальному серверу.
- Проверяет код ответа, заголовки и тело.

Сценарии тестов
- Положительный: подтверждает корректную работу запроса с правильными данными.
- Отрицательный: проверяет правильность сообщения об ошибке при некорректных данных.

Требования к тестам
- Воспроизводимость: результат не должен зависеть от доступности внешних API или секретных ключей.

Дополнительные проверки
- Использование curl для ручного тестирования дополняет автоматические тесты, но не заменяет их.
