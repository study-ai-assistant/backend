Алгоритм – это чёткая последовательность шагов, после выполнения которой задача решается.
Разные алгоритмы могут давать одинаковый результат, но различаются по времени выполнения и потреблению памяти.

Линейный поиск
- Последовательно просматривает элементы массива.
- Работает даже если массив не отсортирован.
- В худшем случае проверяются все n элементов.

Бинарный поиск
- Требует отсортированный массив.
- На каждом шаге сравнивает средний элемент и отбрасывает половину диапазона.
- Число шагов пропорционально log₂ n.

Перед тем как выбрать алгоритм, важно проверить, подходят ли его условия (например, наличие сортировки), а не только сравнивать асимптотику. Для небольших массивов линейный поиск может быть удобнее, несмотря на худшую асимптотику.

Тестирование программ

*Модульный тест* – проверяет отдельный кусок кода, изолируя его от внешних систем.
*Заглушка* (stub) заменяет внешнюю зависимость предсказуемым результатом, например, вместо вызова реальной модели возвращает фиксированный ответ.

*Интеграционный тест* – проверяет совместную работу нескольких компонентов.
*HTTP‑тест* отправляет реальный запрос к локальному серверу и проверяет код ответа, заголовки и тело.

- Положительный сценарий: запрос корректен, сервер отвечает правильно.
- Отрицательный сценарий: запрос содержит ошибку, сервер выдаёт понятную ошибку.

Тесты должны быть воспроизводимыми: их результат не должен зависеть от доступности внешних API или секретных ключей.

*curl* может использоваться для ручной проверки запросов; это дополняет автоматические тесты, но не заменяет их.
