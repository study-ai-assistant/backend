Инвариант
Условие, сохраняемое программой до и после операции (например, уникальность идентификаторов, неотрицательное количество). Проверка инварианта относится к границе изменения данных; при её нарушении операция завершается ошибкой без частичного изменения состояния.

Пустая коллекция допускается, если её контракт не запрещает. Размер входа ограничивается, чтобы избежать дорогих вычислений (например, 1 команда → 12 запросов/мин, лимит 10 → отказ или очередь).

Тестовые наборы включают пустой ввод, один элемент и полный набор. При ошибке на определённом шаге проверяется отсутствие результата и освобождение ресурсов.

Время обработки части фиксировано (например, 3 сек), суммируется для нескольких частей (4 × 3 сек = 12 сек); это не обещание скорости сервиса.

Проверка результата сравнивает вход, контракт и наблюдаемый вывод; название режима должно совпадать в запросе и ответе, числовые значения нельзя округлять так, чтобы изменился смысл.

Перед началом работы проверяется ограничение размера и уникальность. Успешный исход — подтверждение выполнения конкретного запроса. Отказ — код ошибки при превышении лимита или других нарушениях; клиент получает код и описание, но без содержимого документа или секретных настроек, чтобы можно было повторить попытку.

Граничные значения тестируются: максимум, максимум − 1, максимум + 1; превышение лимита даёт одинаковый код отказа при повторных запросах.

При одновременном чтении клиентами состояние согласовано: число завершённых частей ≤ общего числа. После перезапуска память очищается, клиент может повторно отправить запрос. Успешный ответ подтверждает только конкретный запрос, а не отсутствие ошибок в других документах.

Поиск и сложность

Линейный поиск последовательно сравнивает каждый из n элементов с образцом; в худшем случае n сравнений → O(n).

Бинарный поиск работает только на отсортированном массиве, делит диапазон пополам; без сортировки корректность не гарантируется.

O(n) описывает асимптотический рост затрат при росте входа, а не конкретное время; реальные измерения дополняют анализ.

Пример ограничения: система обрабатывает 24 запроса/мин, лимит 20; четыре лишних запроса должны быть отклонены или помещены в очередь с уведомлением клиента.

Тестовый набор из 40 элементов проверяется на пустой ввод, один элемент и полный набор; ошибка на шаге 3 проверяет отсутствие результата и освобождение ресурсов.

Временные расчёты: одна часть = 4 сек → четыре части = 16 сек; ожидание квоты и объединение учитываются отдельно.

Проверка результатов: название режима должно совпадать, числовые значения нельзя округлять так, чтобы менялся смысл.

Граничные значения: максимум, максимум‑1 и максимум+1 обрабатываются одинаково (один код отказа).

При одновременном чтении клиентами состояние согласовано: завершённые части ≤ общее число, успешный запрос содержит итог.

После перезапуска память очищается, клиент может повторно отправить запрос; это свойство временного хранения следует объяснить заранее.

---

Очереди и фоновые задания

Очередь хранит задания в порядке поступления; один исполнитель последовательно берёт следующее задание.

Клиент получает идентификатор задания и проверяет статус: в очереди, выполняется, готово, ошибка. Прогресс показывает количество завершённых частей, а не предполагаемое время. При ошибке нельзя выдавать неполный итоговый ответ.

Временное хранение подразумевает срок удаления; при превышении квоты сервер обязан вернуть отказ или поставить запрос в ограниченную очередь.

Пример расчёта: одна часть = 5 сек, четыре части = 20 сек чистого времени; ожидание квоты и объединение учитываются отдельно.

Тесты: пустой ввод, один элемент, полный набор (60). Ошибка на шаге 4 проверяет отсутствие результата и освобождение ресурсов.

Условия перед запуском: проверка, что запрос не превышает лимит (например ≤ 30 запросов/мин).

Успешный исход — статус «готово» и итоговый результат.

Отказы:
1. Квота превышена — код отказа, сообщение.
2. Ошибка выполнения — код ошибки, без содержимого документа.

Для повторной попытки клиенту нужны: идентификатор задания, код отказа, рекомендация повторить запрос.

Граничные тесты: максимум, максимум − 1, максимум + 1; одинаковый код отказа при повторе.

При одновременном чтении состояние согласовано: завершённые части ≤ общее число, успешное задание имеет итог. После перезапуска память очищается, клиент может повторно отправить запрос.

Наблюдение (ответ сервера) отделяется от вывода о качестве сервиса; проверка требует сравнения с исходным материалом и фиксации ограничений.

Протокол HTTP

Метод GET — чтение состояния ресурса.
Метод POST — создание ресурса или запуск действия.

Ответы сервера:
202 — задание принято, результат ещё не готов; клиент опрашивает URL из заголовка Location с рекомендацией интервала.
400 — неверный запрос.
413 — превышен допустимый размер.
404 — ресурс не найден.

Ограничения запросов: пример 4 — 48 запросов/мин, лимит 40; лишние запросы должны вернуть отказ или попасть в очередь, их нельзя просто терять.

Тестирование наборов (0, 1, N элементов). При ошибке на шаге 5 проверяется отсутствие результата и освобождение ресурсов; вызов функции ещё не гарантирует корректность данных.

Время обработки: одна часть = 6 сек, четыре части = 24 сек (без учёта ожидания квоты и объединения).

Контракт запрос‑ответ: названия режима в запросе и ответе должны совпадать; числовые параметры нельзя округлять так, чтобы менялся смысл условия.

Граничные тесты: проверяются максимум, значение − 1 и + 1; превышение лимита должно давать одинаковый код при повторных запросах.

Конкурентный доступ: одновременно читающие клиенты видят согласованные поля: завершённые части ≤ общее число, успешное задание содержит итог.

Перезапуск — память очищается, клиент может повторно отправить запрос; необходимо объяснить временное хранение.

Успешный ответ подтверждает выполнение конкретного запроса, но не гарантирует отсутствие ошибок в других документах.
