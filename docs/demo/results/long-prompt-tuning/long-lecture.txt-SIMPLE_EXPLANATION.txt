Инвариант – условие, которое программа обязана сохранять до и после каждой операции.
Примеры: уникальные идентификаторы, неотрицательное количество, согласованность полей (число завершённых частей ≤ общее число).

Проверка инвариантов относится к границе изменения данных: при нарушении операция завершается ошибкой и состояние не меняется частично.

Входные данные могут быть пустыми, если контракт их не запрещает. Размер входа ограничивается (например > 10 запросов в минуту), и при превышении лимита сервер обязан вернуть отказ (код 429) или поставить запросы в очередь, а не «терять» их.

Тестирование включает граничные наборы: пустой, один элемент, полный набор. При ошибке проверяется отсутствие результата и освобождение ресурсов.

Временные измерения (память, количество вызовов, длительность) фиксируются отдельно и не заменяют оценку качества ответа.

Если два клиента читают одно состояние, они должны видеть согласованные поля. После перезапуска памяти клиент может потребовать повторную отправку, так как данные не сохраняются.

---

Линейный поиск перебирает элементы последовательно; в худшем случае для n элементов требуется n сравнений (O(n)).
Бинарный поиск работает только с отсортированным массивом, деля диапазон пополам; без предварительной проверки «массив отсортирован» результат может быть неверным.

Оценка O(n) показывает рост затрат при увеличении входа, но не измеряет реальное время; практические измерения на конкретном устройстве дополняют асимптотический анализ.

Успешный исход – запрос выполнен, сервер возвращает результат и подтверждает завершённость.

Отказы:
1) превышен лимит запросов – сервер возвращает код отказа (например 429) и сообщение о перегрузке;
2) неверный формат входа – код ошибки (400, 413 и др.) и указание, какие поля исправить.

Для повторной попытки клиенту нужны код ошибки, описание проблемы и требуемый диапазон допустимых значений.

Граничные тесты проверяют максимум, максимум‑1 и максимум+1; при одинаковом размере данных результаты должны быть одинаковыми.

---

Очередь – структура, где задания сохраняются в порядке поступления. Один исполнитель берёт следующее задание только после завершения текущего; клиент получает лишь идентификатор и проверяет статус отдельно.

Состояния задания:
- в очереди (не запущено);
- выполняется;
- готово (результат полностью готов);
- ошибка (обработка прервана, итоговый ответ не выдаётся).

Прогресс отображает количество завершённых частей, а не предполагаемое время. При ошибке нельзя возвращать неполный итоговый ответ.

Перед началом работы проверяется, не превышает ли количество ожидающих запросов установленный лимит (например 30 запросов в минуту).

Успешный исход – задание переходит в состояние готово и клиент получает полный результат.

Отказы:
1) превышена квота – сервер отвечает кодом отказа и сообщает, что запрос не принят;
2) ошибка выполнения – сервер возвращает код ошибки и описание причины (без содержимого документа).

Для повторной попытки клиенту нужны: идентификатор задания (если был выдан), код отказа, короткое сообщение о причине и рекомендация повторить запрос после ожидания или с изменёнными параметрами.

---

HTTP‑методы и коды:
- GET только читает ресурс;
- POST создаёт/запускает задачу.

Код 202 — задание принято, результат будет готов позже; клиент периодически запрашивает URL из заголовка Location.

Ошибки: 400 (плохой запрос), 413 (слишком большой), 404 (не найдено) – должны возвращаться явно. Сбой внешнего сервиса возвращается с понятным сообщением, без раскрытия секретных данных.

Ограничения нагрузки: если сервер принимает 48 запросов/мин, а лимит 40, лишние запросы нельзя просто потерять – нужно вернуть отказ (429) или поставить запросы в ограниченную очередь.

Тестирование и граничные значения: проверяются пустой набор, один элемент и полный набор (например 80). При ошибке на шаге 5 тест подтверждает отсутствие результата и освобождение ресурсов. Граничные случаи максимум, максимум‑1 и максимум+1 должны давать одинаковый код отказа при повторе.

Повторные попытки клиента: при отказе клиент получает код ошибки, заголовок Retry‑After (или рекомендацию интервала) и, при необходимости, новый URL для повторного POST. Секретные данные и содержимое документа в ошибке не включаются.
