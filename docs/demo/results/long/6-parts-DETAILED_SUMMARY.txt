**Конспект учебного материала**

**1. Данные и инварианты**  
- Инвариант — условие, сохраняющееся до и после операции (например, уникальные ID, неотрицательное количество).  
- Проверка инварианта относится к границе изменения данных; при её нарушении операция завершается ошибкой без частичного изменения состояния.  
- Пустая коллекция допустима, если контракт её не запрещает. Размер входа ограничивается для дорогих вычислений.  
- При превышении лимита запросов (например, 12 запросов/мин при лимите 10) сервер обязан отказать или поставить запрос в очередь, а не «терять» его.  
- Тесты покрывают пустой ввод, один элемент, полный набор; при ошибке на конкретном шаге проверяется отсутствие результата и корректное освобождение ресурсов.  
- Время обработки одной части = 3 сек (в примерах 5 сек или 6 сек); время четырёх частей = 12 сек (или 20/24 сек). Ожидание квоты и объединение считаются отдельно.  
- При проверке сравниваются вход, контракт и наблюдаемый результат; название режима должно совпадать, числовые значения не округляются так, чтобы менялся смысл.  
- При ошибке клиент получает только код и сообщение без конфиденциальных данных; для повторной попытки нужны код отказа, описание ограничения и рекомендация по интервалу повторения.  
- Граничные проверки: максимум, максимум − 1, максимум + 1; превышение лимита даёт одинаковый код при повторных запросах.  
- При одновременном чтении состояние должно быть согласованным; после перезапуска память очищается, клиент может повторить запрос.

**2. Поиск и сложность**  
- Линейный поиск: последовательные сравнения, худший случай = n сравнений → O(n).  
- Бинарный поиск: делит отсортированный диапазон пополам; требует предварительной сортировки, иначе результат неверен.

**3. Ограничения и отказ**  
- При превышении лимита (например, 2–20 запросов/мин, 24 принятых) лишние запросы должны вызвать отказ или попасть в ограниченную очередь.  
- Код отказа одинаков при повторе; детали отказа нужны клиенту, но без раскрытия конфиденциальных данных.  

**4. Тестирование граничных случаев**  
- Проверяются пустой ввод, один элемент, полный набор (40 элем., 60 элем.).  
- Ошибки на шагах 3–7 проверяют отсутствие итогового результата и корректное освобождение ресурсов.  
- Дополнительные граничные значения: максимум, максимум‑1, максимум+1.

**5. Очереди и фоновые задания**  
- Очередь сохраняет порядок поступления; один исполнитель обрабатывает задания последовательно.  
- Клиент получает ID задания и может запрашивать статус: *в очереди*, *выполняется*, *готово*, *ошибка*.  
- Прогресс отображает завершённые части, а не предположительное время.  
- При ошибке части не выдаются как окончательный результат.  
- Временное хранение имеет срок удаления; после перезапуска память очищается, клиент может повторно отправить данные.

**6. Метрики**  
- Пиковая память, число вызовов и длительность измеряются отдельно и не заменяют оценку качества ответа.

**7. Освобождение ресурсов**  
- Вызов функции не гарантирует корректность данных.  
- Чистое время = кол‑во частей × время‑части (например, 4 × 5 сек = 20 сек).  
- При проверке ревьюер сравнивает вход, контракт и наблюдаемый результат; название режима должно совпадать, числа не округляются так, чтобы изменить смысл.  

**8. Условия перед запуском**  
- Проверить соответствие входа контракту (правильный тип, диапазон, размер ≤ максимум).  
- Убедиться, что все части примера полностью загружены.

**9. Успешный исход**  
- Завершённые части ≤ общее число, сервер возвращает итоговое число завершённых частей и подтверждение выполнения конкретного запроса.  

**10. Отказы**  
1. Превышение лимита → код ограничения, рекомендация повторить позже.  
2. Неверный запрос → HTTP 400.  
3. Ошибка согласованности → число завершённых частей > общее, клиент получает код и запрос о корректировке данных.  
4. Нарушение безопасности → отказ без раскрытия содержимого.  

**11. Требования к повторной попытке**  
- Клиенту нужны: код ошибки, описание ограничения, рекомендация по интервалу повторения, идентификатор запроса, текущий счётчик завершённых частей, размер оставшегося материала (при необходимости).  

**12. HTTP‑протокол**  
- GET – чтение ресурса.  
- POST – создание ресурса/запуск действия.  
- 202 – задание принято, результат ещё не готов; клиент опрашивает URL из заголовка Location.  
- 400 – неправильный запрос, 413 – превышение размера, 404 – ресурс не найден.  

**13. Граничные проверки (все разделы)**  
- Проверяются три значения: максимум, максимум‑1, максимум + 1.  
- При одинаковом размере материала сравниваются пиковая память, число вызовов, длительность; они не заменяют оценку качества ответа.  

**14. Согласованность состояния**  
- При одновременном чтении несколькими клиентами число завершённых частей ≤ общее число частей.  
- После перезапуска сервер очищает временное хранилище; клиент может потребовать повторную отправку данных.  

**15. Безопасность**  
- Секретный ключ хранится только на сервере.  
- В ответах об ошибке внешний ответ не копируется полностью.  
- Ограничения размера файла и таймаут защищают память.  
- Файлы с паролем отклоняются.  
- Временные файлы удаляются после завершения или ошибки.  

**16. Ресурсы**  
- Обработка одной части = 8 сек; четыре части = 32 сек (ожидание квоты и объединение учитываются отдельно).  

**17. Тесты**  
- Пустой ввод, один элемент, полный набор.  
- При ошибке на любом шаге проверяется отсутствие результата и освобождение ресурсов.  

**18. Итоги**  
- Успешный ответ подтверждает выполнение конкретного запроса, но не гарантирует отсутствие ошибок в других документах.  
- Для содержательной проверки необходимо сверить определения, вычисления и зафиксировать ограничения, а также описать способ их воспроизведения.
