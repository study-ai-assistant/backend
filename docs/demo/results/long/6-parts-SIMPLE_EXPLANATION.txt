Инвариант — условие, которое должно оставаться истинным до и после любой операции. Примеры: уникальность идентификаторов, неотрицательное количество элементов. Если инвариант нарушается, операция завершается ошибкой без частичного изменения состояния.

Перед запуском задачи проверяется, что размер входных данных не превышает установленный максимум (например, ≤ N байт). Пустая коллекция считается допустимой, если её наличие не запрещено контрактом. Ограничения на количество запросов (например, 20 req/мин) и на размер пакета (например, 413 – превышение лимита) также проверяются до выполнения.

Граничные тесты используют три значения: максимум, максимум ‑ 1 и максимум + 1. При превышении лимита сервер возвращает одинаковый код ошибки (400, 413, 429 и т.п.) и сообщение, позволяющее клиенту повторить запрос после исправления (уменьшить размер, дождаться восстановления квоты). При повторных попытках код ошибки и описание проблемы должны оставаться теми же, что подтверждает детерминированность проверки.

Тестирование охватывает три типа наборов входных данных: пустой, один элемент и полный набор. При ошибке проверяется отсутствие результата и корректное освобождение ресурсов (память, соединения, временные файлы). Вызов функции сам по себе не доказывает корректность данных; необходимо убедиться, что вход соответствует контракту и получен ожидаемый итог.

Очереди и фоновые задания хранятся в порядке поступления, один исполнитель обрабатывает их последовательно. Клиент получает идентификатор задания и может запрашивать статус (в очереди, выполняется, готово, ошибка). Прогресс отображает количество завершённых частей, которое никогда не превышает общее число частей — это согласованное поле, видимое всем клиентам при одновременном чтении.

При успешном завершении сервер возвращает код 200 (или 202 с Location) и тело с итоговым результатом, где завершённые части = общее количество частей. При отказе клиент получает:

* 400 – неверный запрос (неправный формат, недостающие параметры);
* 413 – превышение размера;
* 429 – превышение лимита запросов.

Ответ содержит только код ошибки, краткое описание проблемы, рекомендацию по исправлению и, при необходимости, новый Location для повторного опроса. Конфиденциальные данные (секретные ключи, полный документ) не включаются в ошибочные ответы.

Метрики измерения (пиковая память, число вызовов, длительность) фиксируются отдельно и не заменяют проверку качества ответа; они используются совместно для оценки эффективности.

После перезапуска сервера его память очищается, поэтому состояние, хранящееся только в оперативной памяти, теряется. Клиент обязан повторно отправить данные, если ему требуется восстановить задачу; об этом необходимо информировать заранее.

Таким образом, процесс включает проверку входных ограничений, граничное тестирование, обработку очередей, согласованное отображение прогресса, корректное освобождение ресурсов и предоставление детальной, но безопасной информации для повторных попыток. Все эти элементы обеспечивают предсказуемое, безопасное и воспроизводимое поведение системы.
