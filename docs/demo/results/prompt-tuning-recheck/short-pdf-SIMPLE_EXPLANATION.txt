Алгоритм
Конечная последовательность понятных шагов, приводящая к решению задачи. Разные алгоритмы могут давать один и тот же результат, но отличаться временем выполнения и расходом памяти.

Линейный поиск
- Последовательно просматривает элементы массива.
- Работает в неотсортированном массиве.
- В худшем случае проверяет все n элементов → O(n).

Бинарный поиск
- Требует отсортированный массив.
- После каждого сравнения отбрасывает половину диапазона.
- Число шагов ≈ log₂ n → O(log n).

Выбор алгоритма
Перед выбором нужно убедиться, что выполнены условия применимости (например, сортировка для бинарного поиска). Для маленьких массивов линейный поиск может быть удобнее, даже при более высокой асимптотической сложности.

Тестирование программ

Модульный тест
- Проверяет небольшую часть кода изолированно от внешних систем.

Заглушка (stub)
- Заменяет внешнюю зависимость предсказуемым поведением.
- Пример: вместо вызова модели возвращает заранее заданный ответ.

Интеграционный тест
- Проверяет совместную работу нескольких компонентов.

HTTP‑тест
- Отправляет реальный запрос к локальному серверу.
- Проверяет код ответа, заголовки и тело.

Сценарии тестов
- Положительный: подтверждает корректную работу при правильных данных.
- Отрицательный: проверяет корректную ошибку при неверных данных.

Требования к тестам
- Воспроизводимость: запуск не должен зависеть от доступности внешних API или секретных ключей.

Дополнительные проверки
- Проверка через curl может дополнять автоматические тесты, но не заменяет их.

Пример проекта
- Используются синтетические данные для демонстрации работы алгоритмов и тестов.
