Алгоритм – конечная последовательность понятных исполнителю шагов, решающая задачу. Один и тот же результат может быть получен разными алгоритмами; различаются время выполнения и расход памяти.

Линейный поиск
- Последовательно просматривает элементы массива.
- Работает как в отсортированном, так и в неотсортированном массиве.
- В худшем случае проверяет все n элементов → O(n).

Бинарный поиск
- Требует заранее отсортированный массив.
- После каждой проверки отбрасывает половину диапазона.
- Число шагов ≈ log₂ n → O(log n).

Выбор алгоритма
- Необходимо проверять условия применимости (наличие сортировки, размер данных).
- Для небольших массивов иногда предпочтительнее линейный поиск, несмотря на более высокую асимптотическую сложность.

Тестирование программ

Модульный тест
- Проверяет отдельный компонент в изоляции от внешних систем.

Заглушка (stub)
- Замещает внешнюю зависимость предсказуемым поведением (например, вместо вызова языковой модели возвращает фиксированный ответ).

Интеграционный тест
- Проверяет совместную работу нескольких компонентов.

HTTP‑тест
- Отправляет реальный запрос к локальному серверу.
- Проверяется код ответа, заголовки, тело.
- Положительный сценарий: корректный запрос возвращает ожидаемый результат.
- Отрицательный сценарий: запрос с ошибочными данными возвращает понятную ошибку.

Требования к тестам
- Воспроизводимость: запуск не зависит от доступности внешних API или секретных ключей.

Дополнительные проверки
- Команда curl может использоваться для ручной проверки, но не заменяет автоматические тесты.
