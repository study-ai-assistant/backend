Алгоритм – конечная последовательность понятных исполнителю шагов, позволяющая решить задачу. Разные алгоритмы могут давать один и тот же результат, но отличаться по времени выполнения и расходу памяти.

Линейный поиск  
- Последовательно просматривает элементы массива.  
- Работает с неотсортированными данными.  
- В худшем случае проверяет все n элементов (O(n)).  

Бинарный поиск  
- Требует предварительно отсортированный массив.  
- После каждого сравнения отбрасывает половину оставшегося диапазона.  
- Число шагов растёт пропорционально log₂ n (O(log n)).  

Выбор алгоритма  
- Необходимо проверять условия применимости (наличие сортировки, размер данных).  
- Для небольших массивов часто предпочтительнее линейный поиск, несмотря на худшую асимптотическую оценку.

Тестирование программ  

Модульный тест  
- Проверяет небольшую часть программы изолированно от внешних систем.  

Заглушка (stub)  
- Заменяет зависимость предсказуемым поведением, напр., вместо вызова внешней модели возвращает фиксированный ответ.  

Интеграционный тест  
- Проверяет совместную работу нескольких компонентов.  

HTTP‑тест  
- Отправляет реальный запрос к локальному серверу, проверяет код ответа, заголовки и тело.  
- Положительный сценарий: корректный запрос получает ожидаемый результат.  
- Отрицательный сценарий: при неверных данных возвращается понятная ошибка.  

Требования к тестам  
- Должны быть воспроизводимыми; их результат не должен зависеть от доступности внешних API или секретных ключей.  

Дополнительные проверки  
- Проверка через curl может дополнять автоматические тесты, но не заменяет их.  

Учебный пример проекта использует синтетические данные.
