Алгоритм  
Алгоритм – это чётко описанные шаги, которые приводят к решению задачи. Последовательность конечна, каждый шаг понятен исполнителю. Разные алгоритмы могут давать одинаковый результат, но отличаться по времени выполнения и потреблению памяти.

Линейный поиск  
Линейный поиск просматривает элементы массива один за другим. Работает и с неотсортированными данными. В худшем случае (когда нужный элемент последний или его нет) проверяется все n элементов, поэтому число шагов ≈ n.

Бинарный поиск  
Бинарный поиск требует, чтобы массив был отсортирован. На каждом шаге сравнивается средний элемент и отбрасывается половина диапазона. Число шагов растёт как log₂ n, то есть гораздо медленнее, чем при линейном поиске, но условие (отсортированность) обязательно.

Выбор алгоритма  
Перед тем как выбрать алгоритм, нужно убедиться, что его условия выполнены (например, массив отсортирован для бинарного поиска). Для небольших массивов может быть удобнее простой линейный поиск, несмотря на более плохую асимптотическую оценку.

Тестирование программ  

Модульный тест  
Проверяет отдельный кусок кода без привлечения внешних систем. Позволяет быстро увидеть ошибки в конкретной функции.

Заглушка (stub)  
Заменяет внешнюю зависимость предсказуемым поведением. Пример: вместо вызова реальной языковой модели возвращает заранее заданный ответ. Это делает модульный тест детерминированным.

Интеграционный тест  
Проверяет совместную работу нескольких компонентов программы. Здесь уже задействованы реальные зависимости между модулями.

HTTP‑тест  
Отправляет настоящий запрос к локальному серверу и проверяет ответ: код статуса, заголовки, тело.  

* Положительный сценарий – запрос корректный, сервер отвечает правильно.  
* Отрицательный сценарий – запрос содержит ошибку, сервер возвращает понятное сообщение об ошибке.

Требования к тестам  
Тесты должны быть воспроизводимыми: их результат не должен зависеть от доступности внешних API, секретных ключей и прочих переменных окружений.  

Дополнительные проверки  
Ручной запрос через `curl` может дополнить автоматические тесты, но не заменяет их полностью.  

Таким образом, при выборе алгоритма учитываем условия его применения и реальные размеры данных, а при проверке программ используем модульные, интеграционные и HTTP‑тесты, обеспечивая их детерминированность и воспроизводимость.
