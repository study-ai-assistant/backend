## [Ошибка] LLM добавляет необоснованную гарантию результата алгоритма

- Метка: `bug`.
- Priority: **Medium** — API работает, сценарий записи не блокируется; замечание к содержанию ответа.
- Связано с #61 и #56.
- Основа: `079dc7c`, ветка `59_61`, Groq `openai/gpt-oss-120b`.

### Шаги воспроизведения

1. Запустить backend с Groq.
2. Отправить содержимое `docs/demo/short-text.txt` в `POST /api/v1/text/process`
   с режимом `SIMPLE_EXPLANATION`.
3. Сравнить ответ с исходным текстом. Генерация недетерминирована; конкретная
   формулировка воспроизведена в сохранённом ответе 26 ноября, но не обещается
   при каждом новом запросе.

### Фактическое поведение

Ответ 200 содержит: «Если выполнить все шаги, результат будет гарантирован».
В исходнике такая общая гарантия не утверждается.
Артефакт: `docs/qa/2026-11-26-live/short-text-SIMPLE_EXPLANATION.txt`.

### Ожидаемое поведение

Простое объяснение сохраняет условия и ограничения исходника и не добавляет
безусловную гарантию результата.

### Окружение

Debian Linux, Docker Engine 29.9.2, Compose v5.6.1, Java 21 внутри контейнера,
Groq openai/gpt-oss-120b. Код сервера: 079dc7c.

### Дополнительно

Предлагаемая проверка исправления

Несколько повторов на исходном материале и примерах алгоритмов с явными
предусловиями. Не считать совпадение одной удачной генерации доказательством
устранения ошибки во всех ответах.

После заморозки кода Medium-исправление не должно попадать в main без решения
команды. В этой ветке промпты не менялись.

## [Ошибка] Простое объяснение длинного материала смешивает условия и числа

- Метка: `bug`.
- Priority: **Medium** — запрос проходит, но искажается учебный материал.
- Связано с #61 и #56.

### Шаги воспроизведения

1. Запустить backend с Groq.
2. Отправить `docs/demo/long-lecture.txt` в `POST /api/v1/jobs/materials` с
   `mode=SIMPLE_EXPLANATION`.
3. Дождаться SUCCEEDED и сравнить результат с разделами 1 и 4 исходного текста.
   Формулировки при повторе могут отличаться; доказательство — сохранённый ответ.

### Ожидаемое поведение

Сохраняются условие допустимости пустой коллекции и пары чисел каждого примера:
для 48 запросов ограничение равно 40. Условия разных разделов не смешиваются.

### Фактическое поведение

Ответ сначала допускает пустой ввод, а затем пишет «Контракт функции требует
проверки входных условий (непустой ввод, соблюдение лимитов) перед запуском».
Также приведено «48 при лимите 30», хотя в исходнике для 48 запросов лимит 40.

Артефакт: `docs/qa/2026-11-26-live/long-txt-SIMPLE_EXPLANATION.txt`.
Время: 26.11.2026, 13:09:03 +03:00; SUCCEEDED, 4 части, 183,42 секунды.

### Окружение

Debian Linux, Docker Engine 29.9.2, Compose v5.6.1, Java 21 внутри контейнера,
Groq openai/gpt-oss-120b. Код сервера: 079dc7c, ветка 59_61.

### Дополнительно

В промптах уже есть запрет смешивать числа и усиливать утверждения.
Нужна проверка промежуточных ответов и объединения на нескольких повторах,
а не только добавление ещё одной общей инструкции.
После заморозки исправление Medium согласуется с командой; в этой ветке
промпты не менялись.

## [Ошибка] KEY_TERMS приписывает квоте учёт времени ожидания

- Метка: `bug`.
- Priority: **Medium** — результат возвращается, но определение неточно.
- Связано с #61 и #56; похожее замечание ранее отмечалось при проверке #48.

### Шаги воспроизведения

1. Отправить `docs/demo/long-lecture.txt` в `POST /api/v1/jobs/materials` с
   `mode=KEY_TERMS`.
2. Дождаться SUCCEEDED и сравнить определение квоты с исходником.
3. Для недетерминированного ответа использовать сохранённый артефакт ниже.

### Ожидаемое поведение

Модель не выводит новое определение из соседних упоминаний. Если определения
нет в материале и его нельзя достоверно передать по исходнику, термин пропускается.

### Фактическое поведение

«Квота (quota) — ограничение, учитывающее как время ожидания, отдельное от чистого
времени выполнения частей, так и количество запросов за единицу времени».
Источник говорит, что ожидание квоты добавляется к времени частей отдельно,
а не что сама квота учитывает это время ожидания.

Артефакт: `docs/qa/2026-11-26-live/long-txt-KEY_TERMS.txt`.
26.11.2026, 13:14:06 +03:00, SUCCEEDED, 4 части, 177,43 секунды.

### Окружение

Debian Linux, Docker Engine 29.9.2, Compose v5.6.1, Java 21 внутри контейнера,
Groq openai/gpt-oss-120b, код сервера 079dc7c, ветка 59_61.

### Дополнительно

Проверить выделение терминов по частям и объединение. Исправление Medium после
заморозки согласуется с командой; в этой ветке модель и промпты не менялись.
