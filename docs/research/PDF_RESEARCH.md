# Исследование PDF — задача #23

Дата проверки: 04.11.2026. Стек прототипа: OpenJDK 21, Apache PDFBox 3.0.8.
Это результаты исследования, **PDF API в backend ещё не реализован**.

## Выбор библиотеки

Выбран `org.apache.pdfbox:pdfbox:3.0.8`, Apache License 2.0.
На дату проверки это актуальный релиз ветки 3.0.x на
[официальной странице загрузок](https://pdfbox.apache.org/download.cgi).
PDFBox поддерживает извлечение текстового слоя, кириллицу при корректных шрифтах,
постраничное чтение и работу с локальным файлом. Подходит для Java-проекта без
внешнего сервиса. Apache Tika даёт больше форматов, но для одного PDF добавляет
ненужный слой; OCR и распознавание таблиц не являются целью этого прототипа.

В 3.x загрузка выполняется через `Loader`, а не старый `PDDocument.load`.
[Руководство миграции](https://pdfbox.apache.org/3.0/migration.html) описывает
`Loader.loadPDF(File)` и файловый reader. Использовался PDFTextStripper с сортировкой
по позиции; каждый документ закрывался после извлечения.

## Прототип и результаты

Прототип выполнен отдельно от Git-репозитория backend. В pom.xml приложения PDFBox
не добавлен, HTTP-маршрут по-прежнему принимает только TXT. Код прототипа не должен
входить в PR этой ветки — требование #23.

Для воспроизводимой проверки созданы три синтетических PDF с известным текстом,
встроенным DejaVu Sans и без персональных данных. После сохранения каждый PDF
заново открыт через Loader; извлечённый текст сравнен с эталоном целиком, включая
кириллицу и порядок страниц. Только внешние пробельные символы результата удалены.

| Файл | Содержание | Страниц | Размер, байт | Unicode-кодовых точек | Результат |
|---|---|---:|---:|---:|---|
| plain.pdf | Английский текст о фотосинтезе | 1 | 6274 | 58 | Полное совпадение |
| russian.pdf | Русский текст, включая Ё | 1 | 7867 | 62 | Полное совпадение |
| multipage.pdf | Три страницы о круговороте воды | 3 | 7727 | 101 | Полное совпадение и порядок страниц |

Это проверка базовой технической возможности, а не измерение качества на реальных
лекциях. Двухколоночные документы, сканы, формулы и таблицы в эти три образца не входят.
Перед выпуском PDF API потребуется отдельный набор таких материалов.

## Ограничения и решения для Спринта 3

- **Сканы без текстового слоя:** обычное извлечение не распознаёт изображение.
  Предлагается понятная ошибка «Нет текстового слоя; нужен OCR», без отправки пустого
  текста в LLM. OCR вынести в отдельную задачу.
- **Порядок текста:** PDF хранит графические команды; порядок слов/колонок может
  отличаться от визуального. Сортировка по координатам не гарантирует правильный
  результат для колонок и таблиц. Это также отмечено в
  [FAQ PDFBox](https://pdfbox.apache.org/2.0/faq.html#text-extraction).
- **Таблицы:** PDFTextStripper возвращает текст, не модель строк и столбцов.
  Структура может потеряться; не обещать восстановление таблиц в первом релизе.
- **Формулы и шрифты:** индексы, дроби и символы могут извлекаться в другом порядке;
  некорректные таблицы Unicode в исходном PDF могут давать искажённые символы.
  Нужны эталоны и ручная проверка, нельзя считать успешный HTTP 200 гарантией точности.
- **Размер и ресурсы:** маленький PDF может быть сложным для парсинга. Предложение:
  сохранить 10 МиБ на файл и лимит текста 10000, добавить максимум 50 страниц,
  отдельный таймаут парсинга 10 секунд и ограничение параллельных разборов.
  Эти значения предварительные, требуют нагрузочного теста; сейчас не реализованы.
- **Защита/повреждение:** зашифрованные и повреждённые PDF отклонять понятными ошибками;
  не обходить запрет извлечения. Проверять сигнатуру и результат парсинга, не только
  расширение или MIME. Временные файлы удалять в finally, не логировать содержимое.
- **LLM:** после извлечения применять те же проверки текста, что для JSON/TXT.
  Превышение лимита не обрезать молча. Обработку по частям согласовать отдельно.

## Предлагаемые задачи Спринта 3

1. Обновить OpenAPI: добавить PDF к одному полю file, определить ошибки скана,
   пароля, повреждения и лимитов; согласовать сообщения с mobile.
2. Подключить PDFBox 3.0.8 (повторно проверить версию перед реализацией), сделать
   PdfTextExtractor и выбор экстрактора, сохранив рабочий TXT.
3. Добавить ограничения страниц/размера/времени и очистку временных ресурсов.
4. Покрыть HTTP-тестами PDF на русском, многостраничный PDF, скан, таблицу,
   формулы, зашифрованный/повреждённый PDF, превышение лимитов и ошибку LLM.
5. Провести проверку на реальных учебных документах, оценить память/время,
   обновить API/wiki и примеры curl; OCR и чанкинг планировать отдельно.
