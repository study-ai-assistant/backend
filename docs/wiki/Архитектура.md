# Архитектура backend

## Решения

| Вопрос | Решение | Основание |
|---|---|---|
| Язык | Java 21 | Выбор backend-команды в ветке выбора стека |
| Сервер | Spring Boot 4.1.1, Spring MVC | REST API и multipart |
| Сборка | Maven 3.9.9 через Wrapper | Воспроизводимая сборка без отдельной установки Maven |
| Тестирование | JUnit, Spring Boot Test, HTTP-клиент Java | Проверка реального локального HTTP-сервера |
| Проверка стиля | Checkstyle | Правила находятся в config/checkstyle/checkstyle.xml |
| База данных | Пока не требуется | Нет истории, аккаунтов и постоянного хранения |
| Адаптер LLM | Spring AI предусмотрен выбранным стеком; подключение в #8 | Не реализован в текущем скелете |
| LLM | Каждый backend-разработчик выбирает своего | Обновлённое требование #6 |
| Локальный запуск для mobile | Docker Compose или JDK 21 | Один сервер на порту 8080 |

## Поток запроса

Мобильный клиент → HTTP API Spring MVC → сервис обработки → LlmClient → внешний API.
Результат возвращается мобильному клиенту в JSON. Реальный LlmClient и эндпоинт
обработки текста относятся к #8 и сейчас не реализованы.

`health` — рабочая проверка сервера. `material` — прежний каркас загрузки файлов;
`extraction` и `llm` — точки расширения. `LlmProperties` читает параметры из окружения
и не раскрывает ключ через toString. Секреты не попадают в DTO и не отдаются через API.
Загруженные документы пока не сохраняются. OCR и парсеры — будущая работа.

Секреты не встраиваются в JAR и Docker-образ: для запуска передаются окружением.
Настройки по умолчанию позволяют запустить /health без ключа и без .env.

Это локальная редакция. Решения по mobile не принимаются от имени mobile-команды;
при публикации сверить актуальную таблицу команды и сохранить существующие решения.
