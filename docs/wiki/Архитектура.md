# Архитектура backend

## Решения

| Вопрос | Решение | Основание |
|---|---|---|
| Язык | Java 21 | Выбор backend-команды в ветке выбора стека |
| Сервер | Spring Boot 4.1.1, Spring MVC | REST API и multipart |
| Сборка | Maven 3.9.9 через Wrapper | Воспроизводимая сборка без отдельной установки Maven |
| Тестирование | JUnit, Spring Boot Test, HTTP-клиент Java | Проверка реального локального HTTP-сервера |
| Проверка стиля | Checkstyle | Правила находятся в config/checkstyle/checkstyle.xml |
| База данных | Пока не требуется | Нет истории, аккаунтов и постоянного хранения |
| Адаптер LLM | GroqLlmClient на Spring RestClient | Реализация №8; Spring AI не подключён |
| LLM | Сейчас поддержан Groq; ключ и модель локальные | Для другого провайдера нужен отдельный адаптер |
| Локальный запуск для mobile | Docker Compose или JDK 21 | Один сервер на порту 8080 |

## Поток запроса

Мобильный клиент → HTTP API Spring MVC → сервис обработки → LlmClient → внешний API.
Результат возвращается мобильному клиенту в JSON. TextProcessingController проверяет
text/mode и вызывает GroqLlmClient. Текст и системная инструкция передаются разными
сообщениями; в ответ извлекается choices[0].message.content. Работают все пять режимов.
Неизвестный режим — 400. Сбой Groq, квота и ожидание более 60 секунд — 502.

`health` — рабочая проверка сервера. `material` — JSON API и загрузка одного TXT;
`extraction` и `llm` — точки расширения. `LlmProperties` читает параметры из окружения
и не раскрывает ключ через toString. Секреты не попадают в DTO и не отдаются через API.
Загруженные документы пока не сохраняются. TxtTextExtractor читает UTF-8/Windows-1251; PDF, DOCX и OCR — будущая работа.

Секреты не встраиваются в JAR и Docker-образ: для запуска передаются окружением.
Настройки по умолчанию позволяют запустить /health без ключа и без .env.

Это локальная редакция. Решения по mobile не принимаются от имени mobile-команды;
при публикации сверить актуальную таблицу команды и сохранить существующие решения.

Исследование PDF для Спринта 3: [выводы](../research/PDF_RESEARCH.md).
Прототип изолирован от основного приложения; зависимости PDFBox в pom.xml backend нет.

## Обработка PDF

MaterialService проверяет расширение и содержимое. PdfTextExtractor сохраняет
данные в отдельную временную папку и запускает ту же сборку приложения в режиме
worker. Этот режим не запускает Spring и не читает .env. Окружение дочернего
процесса очищено; ключ LLM в него не передаётся. Worker вызывает PDFBox и отдаёт
текст либо понятную ошибку через локальный бинарный файл. HTTP-ответ не меняется.

PdfProperties читает лимиты из app.pdf. Semaphore ограничивает число процессов;
очереди нет, перегрузка возвращает 503. При таймауте процесс завершается
принудительно; после его остановки удаляются все файлы и освобождается слот.
Heap и metaspace ограничены отдельно. Извлечённый текст передаётся в LLM только
после успешного разбора и общих проверок; исходный PDF и текст не логируются.

Запуск worker поддержан для IDEA/Maven и исполняемого JAR, включая Docker.
Выбор ограничений подтверждён [замерами](../research/PDF_VALIDATION.md).
