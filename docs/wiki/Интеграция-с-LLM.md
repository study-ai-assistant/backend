## Настройки сервера

Файл .env.example содержит пустые значения и комментарии; скопируйте его
в .env и заполните свой файл. Для Groq локальные значения:

```properties
LLM_PROVIDER=groq
LLM_MODEL=openai/gpt-oss-120b
LLM_BASE_URL=https://api.groq.com/openai/v1
```

LLM_API_KEY заполните самостоятельно своим новым ключом. В документации
и сообщениях ключ не показывать. Сервер привязывает параметры к LlmProperties;
вызов API будет добавлен в #8, которая исключена из текущей работы.
Для альтернативного провайдера понадобится соответствующий адаптер.

Groq Console: https://console.groq.com/ → API Keys → Create API Key.
Ключ хранится только в локальном .env либо окружении процесса; .env исключён
из Git и Docker-контекста. Не передавать ключ участникам, в Issues, PR, чат,
коммиты, curl-примеры или логи. Не выводить LlmProperties.getApiKey().

## Лимиты Groq

На 23.10.2026 опубликованные базовые ограничения Free Plan для
openai/gpt-oss-120b: 30 запросов/мин, 1000 запросов/день, 8000 токенов/мин,
200000 токенов/день. Лимиты действуют на организацию, не на каждый ключ.
Проверяйте индивидуальные квоты в Console → Limits: условия меняются.
Источник: https://console.groq.com/docs/rate-limits.
Контекст модели не отменяет квот тарифа. В #8 нужно отдельно проверять
токенный бюджет и не включать бесконечные повторы при 429.

## Режимы

| Идентификатор | Результат |
|---|---|
| SHORT_SUMMARY | Краткий конспект |
| DETAILED_SUMMARY | Подробный конспект |
| SIMPLE_EXPLANATION | Объяснение простыми словами |
| SELF_CHECK_QUESTIONS | Вопросы для самопроверки |
| KEY_TERMS | Ключевые термины |

Идентификаторы соответствуют ProcessingMode и OpenAPI. Сейчас генерация
не реализована ни для одного режима; в #8 первым делается SHORT_SUMMARY.
Примеры учебных текстов для ручной проверки не должны содержать персональные данные.

## Если ключ раскрыт

1. В личном кабинете провайдера немедленно отозвать раскрытый ключ.
2. Создать новый, записать в свой .env и перезапустить сервер/контейнер.
3. Проверить историю использования в Console, сообщить руководителю о факте
   утечки без самого ключа.
4. Проверить Git, CI и логи. Если секрет попал в историю Git — согласовать
   очистку истории с руководителем. Удаление строки не заменяет отзыв ключа.
5. Не отправлять новый ключ в чат. Смену ключа выполняет владелец аккаунта.
