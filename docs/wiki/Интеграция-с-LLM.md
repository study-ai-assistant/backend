## Настройки сервера

Файл .env.example содержит пустые значения и комментарии; скопируйте его
в .env и заполните свой файл. Для Groq локальные значения:

```properties
LLM_PROVIDER=groq
LLM_MODEL=openai/gpt-oss-120b
LLM_BASE_URL=https://api.groq.com/openai/v1
```

LLM_API_KEY заполните самостоятельно своим новым ключом. В документации
и сообщениях ключ не показывать. Сервер привязывает параметры к LlmProperties;
GroqLlmClient вызывает API для всех пяти режимов; JSON и TXT используют один клиент.
Для альтернативного провайдера понадобится соответствующий адаптер.

Groq Console: https://console.groq.com/ → API Keys → Create API Key.
Ключ хранится только в локальном .env либо окружении процесса; .env исключён
из Git и Docker-контекста.

## Лимиты Groq

Для `openai/gpt-oss-120b` на Groq Free Plan действуют лимиты: 30 запросов в минуту,
1 000 запросов в сутки, 8 000 токенов в минуту и 200 000 токенов в сутки.
Точные лимиты своей организации проверяйте в [Groq Console](https://console.groq.com/settings/limits).
[Документация Groq](https://console.groq.com/docs/rate-limits).

При превышении лимита Groq возвращает `429`, а наш API — `502` с сообщением
об исчерпании лимита. Повторите запрос после сброса квоты. Если один материал
превышает минутный бюджет токенов, сократите его или обработайте по частям.

## Режимы

| Идентификатор | Результат |
|---|---|
| SHORT_SUMMARY | Краткий конспект |
| DETAILED_SUMMARY | Подробный конспект |
| SIMPLE_EXPLANATION | Объяснение простыми словами |
| SELF_CHECK_QUESTIONS | Вопросы для самопроверки |
| KEY_TERMS | Ключевые термины |

Идентификаторы соответствуют ProcessingMode и OpenAPI. Все пять режимов
поддерживаются для JSON-текста и TXT. Неизвестный идентификатор возвращает 400.
Примеры учебных текстов для ручной проверки не должны содержать персональные данные.

## Промпты для длинных материалов

В `LlmPrompts` для каждого из пяти режимов есть два промпта.
`forChunk` обрабатывает одну часть текста, а `forMerge` собирает ответы
по частям в один итоговый результат.

| Режим | Обработка части (`forChunk`) | Объединение ответов (`forMerge`) |
|---|---|---|
| `SHORT_SUMMARY` | Выделяет главные мысли и важные факты части. | Убирает повторы и собирает краткий конспект всего материала. |
| `DETAILED_SUMMARY` | Извлекает определения, факты, примеры и формулы. | Собирает подробный конспект по темам, сохраняя условия, исключения и связи между идеями. |
| `SIMPLE_EXPLANATION` | Объясняет идеи части простыми словами. | Выстраивает одно последовательное объяснение и убирает повторы. |
| `SELF_CHECK_QUESTIONS` | Составляет вопросы, ответы на которые есть в части. | Убирает вопросы с одинаковым смыслом и оставляет до 10 вопросов на весь материал, без ответов. |
| `KEY_TERMS` | Выделяет термины и даёт определения по тексту части. | Объединяет варианты названия одного понятия и оставляет одно определение. Английский перевод термина указывается в скобках. |

### Ручная проверка

Через `LongMaterialPromptManualTest` проверены все пять режимов на
`docs/api/examples/llm-quality/long-lecture.txt` (4 части) и на вводной
лекции MIT 6.006 по алгоритмам в PDF (2 части). В обоих случаях режим
самопроверки вернул по 10 вопросов без явных дублей.

В первом прогоне `KEY_TERMS` на PDF модель дала отдельные определения
под русскими и английскими названиями. После уточнения промпта
объединения повторный прогон убрал обе найденные пары дублей.
Формат названий оставался неоднородным.

В некоторых ответах осталось Markdown-выделение. В одном прогоне
на TXT последнее определение оборвалось.

## Реальный вызов и диагностика

Нужны все параметры LLM_PROVIDER=groq, LLM_MODEL, LLM_BASE_URL и LLM_API_KEY.
URL вызова: базовый URL без завершающего слеша + /chat/completions.
Ключ передаётся как Authorization: Bearer только между сервером и Groq.
Отсутствие настроек даёт 502 при обработке, но не мешает запуску /health.

Подключение ограничено 5 секундами; read timeout и общее ожидание — 60 секунд.
При исчерпании лимита, таймауте или недоступности Groq сервер возвращает `502`
с отдельным сообщением в `detail` для каждой причины. В логах фиксируется
причина сбоя без ключа, текста материала и тела ответа Groq.
LLM может сформулировать конспект по-разному. Система просит русский обычный текст
без добавления фактов, но качество нужно проверять на реальных учебных примерах.
Инструкция не является гарантией защиты от всех инструкций внутри материала.

Тесты GroqLlmClient используют локальный имитатор HTTP API и не расходуют реальную квоту.
Для ручной проверки: заполнить свой .env, перезапустить сервер и отправить пример
из docs/api/examples/short-summary-request.json по инструкции docs/api/README.md.

## Части и объединение

GroqLlmClient использует LlmPrompts.forChunk и LlmPrompts.forMerge для всех
пяти режимов. Промпты частей сохраняют факты и условия исходника. Итоговый
запрос получает ответы в порядке частей и убирает повторы. Вопросы ограничены
десятью на весь материал; при объединении выбираются до шести разных вопросов, ответы и подтверждающие фрагменты остаются только
на промежуточном этапе. Термины объединяются с синонимами в одно определение.
Краткий конспект ограничен 3–6 предложениями, подробный сохраняет порядок тем,
простое объяснение связывает понятия без повторения одинаковых примеров.

Для части дополнительно задан компактный ответ до 150 слов, до 4 вопросов
или до 8 терминов. Для GPT-OSS используется reasoning_effort=low. Максимум completion: 1600 для
части, 1600 для целого материала и 2400 для объединения; reasoning тоже входит в этот
бюджет. finish_reason=length считается ошибкой: обрезанный ответ не выдаётся
за готовый. Usage вызовов, сообщённый провайдером, суммируется в метаданные задания.
На квоту резервируются вход, инструкции, 64 служебных токена и максимальный
выход. При другой модели нужно проверить токенизацию и допустимость параметров.

Ручной прогон на TXT/PDF и сохранённые ответы описаны в docs/demo/README.md.
Обычные тесты не обращаются к Groq. Публикация этой страницы выполняется отдельно.

Короткий синхронный запрос не ждёт освобождения минутной квоты: при занятости
получает 502 с описанием лимита, как при внешнем 429. Ожидание выполняется
только фоновыми заданиями. Поэтому синхронный маршрут сохраняет прежний
сетевой таймаут 60 секунд и рекомендацию клиенту 90 секунд.
